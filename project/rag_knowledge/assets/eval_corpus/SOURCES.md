# 评测语料来源与许可

本目录的 15 篇 md 是 **rag_knowledge 评测语料 (C17)**，全部是**网络与数据领域的
政府公开文本**，由 `scripts/build_eval_corpus.py` 从官方发布页生成。

**重建方式**（原文由脚本自己抓并缓存到系统临时目录，无需手工下载）：

```bash
python scripts/build_eval_corpus.py
```

## 二、为什么是政府文本

先试过一轮**官方技术文档**（FastAPI / Vue / Pinia 的中文文档站），弃用：那类 md 是
**给渲染器写的中间产物**，不是给人读的文本 —— 站点容器语法（`::: tip` / `/// tip`）、
标题锚点、HTML 组件、推广链接、甚至**外链的代码引用**（FastAPI 的正文里没有代码，
只有 `{* ../../docs_src/x/y.py *}` 这样的指针，800 余处）全都混在里面。清洗能清掉
大部分，但那份语料始终是"加工出来的"。

政府文本没有这个问题：它**本来就为阅读而发布**。纯文字、章条结构、无代码、无图片、
无站点语法。

**版权**：依《中华人民共和国著作权法》第五条，法律、法规，国家机关的决议、决定、
命令和其他具有立法、行政、司法性质的文件，**不适用著作权法**。

**主题一致性是有意的**：15 篇全部落在「网络与数据合规」这一个领域，构成一个真实的
企业合规知识库。这比"几个互不相干的行业拼在一起"对评测更有用 —— 同族文件之间大量
共享术语与句式（《数据出境安全评估办法》《个人信息出境标准合同办法》《促进和规范
数据跨境流动规定》三件套尤其接近），检索必须真做区分才分得开，而这正是 rerank
开/关消融能测出差别的前提。

## 三、清洗规则（由 `build_eval_corpus.py` 执行）

政府网页里混着导航、目录与页脚（版权 / ICP 备案 / 编辑署名）。切法两头夹：

- **头**：从**精确等于文号名**的那一行起。页面 `<title>` 带站点后缀，靠它定位会把
  导航和目录一起带进来；正文从「第一条之前最后一个章标题」起 —— 目录里也有一串
  同名的章标题，取最后一个才是正文里那一个。标题行有错字时（见上文密码法）退一步，
  认「不含书名号 + 长度接近法名 + 含法名末尾三字」的那一行。
- **尾**：用末条的「自……起施行。」收尾 —— 它必定是全篇最后一句。两种写法都认：
  「自 2021 年 9 月 1 日起施行」与「自公布之日起施行」。
- 「第一章 …」→ `## 第一章 …`，「第一节 …」→ `### 第一节 …`。

**刻意没有做的事**：不改动任何条文 —— 不合并、不改写、不删节。语料可以做清洗，
但不能被"写作"，否则评测测的就是我写的东西。

**一处已知的加工**：早期政府网页的条号用全角空格分隔，脚本统一归一化成半角，
使「第 X 条」在语料里格式一致。
