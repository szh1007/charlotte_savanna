# ③ 安全（#23-30）

> 返回 [难点清单索引](../README.md#难点清单)

| ID | 难点 | 详细细节 | 阶段 |
|----|------|----------|------|
| 23 | Prompt Injection 防护 | • 致命三合一：不可信输入（用户 / 外部文档）+ 私有数据（系统里的敏感信息）+ 对外通信（工具能联网 / 发消息），三者齐备才构成真正的注入危害 | P1 |
| | | | • 纵深防御：在输入、检索、工具、输出四层都设护栏，单层被绕过还有下一层兜底 | |
| | | | • 外部文档（网页、上传文件）只能当 data 读取，不能当 instruction 执行 | |
| | | | • 越狱（绕过系统指令）和知识库投毒（污染检索数据）都是注入的变体，要一并防 | |
| | | | • 红队 / 对抗测试：主动构造攻击样本，验证防护是否真的有效 | |
| 24 | 工具沙箱/最小权限 | • 数据库用只读账号，agent 不能随便写库 | P1 |
| | | | • SQL 白名单：只允许 SELECT 等只读语句，禁止 DROP / DELETE | |
| | | | • 命令白名单 + 目录限制：只能执行白名单里的命令，只能访问限定的目录 | |
| | | | • 参数校验：防止 SQL 注入、路径穿越等攻击 | |
| 25 | HITL 高危操作审批 | • 高危操作（转账、删数据、发邮件）执行前必须人工确认 | P1 |
| | | | • 用 needs_approval 标记这类操作，runtime 检测到就挂起 | |
| | | | • 挂起后等待人工批准或拒绝，绝不自动执行 | |
| | | | • 挂起点要持久化（记录挂起在哪个 tool_call、审批上下文），审批后从断点恢复执行，而非从头重跑 | |
| | | | • 审批超时 / 拒绝的处理：拒绝要回填失败原因给模型，超时要走降级路径 | |
| 26 | 敏感信息脱敏 | • PII（手机号、身份证、邮箱）在进入日志前先脱敏 | P1 |
| | | | • 日志和 trace 里绝不能出现 API Key、token 等凭据 | |
| | | | • 结构化脱敏：按字段类型脱敏（知道这是个手机号就按手机号规则打码），而不是靠正则碰运气 | |
| 27 | 审计/合规轨迹 | • 审计要求：合规官能根据记录，重构出 agent 当时的完整推理路径（为什么这么回答、调了哪个工具、访问了哪条数据） | P1 |
| | | | • 每次工具调用、每次数据访问都要留审计记录 | |
| | | | • 全链路可回溯：从输入到输出，每一步都能追溯 | |
| 28 | 数据合规删除权 | • GDPR 被遗忘权：用户要求删除时，其数据（对话、记忆、日志、审计记录）要能物理删除，而非仅软删除标记 | P2 |
| | | | • 记忆系统 #33 的软删除与合规删除是两回事：软删除为可追溯，合规删除为彻底移除 | |
| | | | • 删除的传播：删除用户数据要级联到衍生数据（向量、checkpoint 快照、trace） | |
| | | | • 删除后要能证明已删（审计删除操作本身），不能「删了但检索还能搜到」 | |
| 29 | 输出护栏 + 幻觉控制 + 引用溯源 | • Output guardrail：输出有害内容过滤、格式校验、二次 PII 检查、防越权信息泄露（数据出逃） | P1 |
| | | | • 幻觉成因：训练数据偏差、采样随机、上下文不足、长尾知识 | |
| | | | • 幻觉缓解：grounding（强制基于检索结果回答）、低置信转人工、明确「不知道」的拒答策略 | |
| | | | • 引用溯源（citation）：RAG 回答带来源、逐句引用，便于用户核查，也是落地 RAG 应用的标配 | |
| | | | • 输出侧也防注入：工具返回内容被模型当指令执行、外部数据污染输出，输出侧同样要有护栏 | |
| 30 | SSRF + RBAC + 密钥管理 | • SSRF（Server-Side Request Forgery，服务端请求伪造）：攻击者诱导服务端去请求攻击者指定的地址；agent 的 fetch URL 类工具（网页搜索、文件下载）就是攻击面——若不对地址做校验，攻击者可以让服务端去访问内网地址，绕过防火墙窃取内网信息。防护：校验目标地址、禁止内网 IP / 私网网段 | P1 |
| | | | • RBAC（Role-Based Access Control，基于角色的访问控制）/权限模型：不只是 #32 的多租户隔离，还有角色（谁有权调高危工具） | |
| | | | • 密钥管理：API Key 不进代码、运行时注入、KMS（Key Management Service，密钥管理服务）、定期轮换 | |
