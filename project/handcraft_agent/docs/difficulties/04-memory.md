# ④ 记忆（#31-33）

| ID | 难点 | 详细细节 | 阶段 |
|----|------|----------|------|
| 31 | 记忆分层（短期 / 情景 / 语义 / 程序性四层） | • 短期记忆：当前对话的上下文 | P2 |
| | | | • 情景记忆：带时间戳的历史事件记录（某年某月用户说过什么） | |
| | | | • 语义记忆：向量化的知识（「用户偏好 X」） | |
| | | | • 程序性记忆：行为模式（「用户遇到问题会先查 FAQ」） | |
| | | | • 记忆冲突时用时间衰减（recency weighting）解决，新记忆权重高于旧记忆 | |
| | | | • 记忆废弃用软删除标记，不物理删除，保留可追溯性 | |
| 32 | 多租户隔离 | • 每条数据、每条记忆都带 tenant_id / user_id 元数据 | P2 |
| | | | • 检索时强制 `WHERE user_id = ...` 过滤，从根上杜绝跨租户数据泄露 | |
| | | | • 这是多租户 SaaS 的硬性安全要求，不能靠「相信模型不乱看」 | |
| 33 | 记忆机制（写入 / 检索 / 遗忘） | • 写入决策：谁决定写记忆（显式规则 vs 记忆 agent），写什么（事实 vs 偏好 vs 事件） | P2 |

| | | | • 遗忘机制：recency decay（时间衰减）、容量淘汰（LRU，Least Recently Used，最近最少使用 / 重要度排序） | |
| | | | • 记忆冲突解决：新记忆覆盖旧记忆，软删除保留可追溯 | |
