# ⑤ 成本（#34-37）

| ID | 难点 | 详细细节 | 阶段 |
|----|------|----------|------|
| 34 | 成本追踪 | • 按 task 归因成本（一次任务总共花了多少钱），而不是只盯着单个 token 价格 | P2 |
| | | | • token 归因：哪一步、哪个工具、哪个模型各花了多少 token，能拆解清楚 | |
| | | | • 预算硬上限：per user / per tenant 设预算，超了就拒绝，防止单用户烧穿 | |
| | | | • 成本告警：成本出现尖峰时告警 | |
| 35 | Token 计量与成本预估 | • tiktoken / BPE 原理：token 不是字符，中文 / 代码 / 特殊符号的 token 化差异大 | P1 |
| | | | • 不同模型 tokenizer 不同，token 数不同，成本核算要按实际模型算 | |
| | | | • 请求前预估 token（输入消息 + 预留输出窗口 + 工具结果空间）做预算硬截断（关联 #3） | |
| | | | • 预估 vs 实际：流式输出实际 token 以 usage 返回为准，预估用于提前止损 | |
| 36 | 模型分级路由 + 语义缓存 | • 分级路由：简单步骤（分类、抽取）用便宜模型，难推理用强模型，从而省成本 | P2 |
| | | | • 语义缓存：高频相似问题命中缓存直接返回，不重复调 LLM | |
| | | | • 缓存穿透：查询不存在的 key 每次都打到后端，用空值缓存或布隆过滤器兜底（布隆过滤器：用少量内存近似判断「key 是否存在」的概率型数据结构，判断不存在就直接返回，不查后端） | |
| | | | • 缓存击穿：热点 key 过期瞬间大量并发打后端，用互斥锁 / 热点永不过期 | |
| | | | • 缓存雪崩：大量 key 同时过期，用随机 TTL 错开过期时间 | |
| | | | • prompt 缓存：相同前缀命中缓存 | |
| | | | • 模型网关：统一治理多模型的路由、限流、计费 | |
| 37 | Batch API 降本 | • Batch API：把多个请求打包异步处理，通常可降约 50% 成本，但延迟高（结果数小时到一天返回） | P2 |
| | | | • 适用场景：离线评估跑分、批量数据标注 / 分类、数据飞轮 #60 的批量处理 | |
| | | | • 不适用：实时交互（客服、对话），延迟敏感场景 | |
| | | | • batch 结果回填：任务 id 轮询结果，失败重试，与实时请求的幂等键统一 | |
