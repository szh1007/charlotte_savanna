# ADR-0002: 付费能力以「会员密钥」验证模拟，不接真实支付

- 日期：2026-08-19
- 状态：已接受

## 背景

需求希望「增加付费能力」，同时这是学习项目：要求后端轻量、无数据库。真实支付（订单、回调、对账、退款）会显著放大复杂度，超出学习范围。

## 决策

在 `.env` 中配置一个会员密钥（`MEMBER_KEY`）。前端输入密钥后由后端校验，校验通过则该会话解锁会员档能力。免费档与会员档存在真实功能差异（清晰度上限、并发数、队列长度、交付有效期），由后端强制校验，不是 UI 摆设。

## 后果

- 零数据库、零支付网关、零外部依赖，符合轻量约束
- 付费差异逻辑是真实可用的，未来接真实支付时只需替换「密钥校验」为「订单回调」，差异逻辑全部保留
- 密钥是共享的（所有会员同一密钥），不模拟账号体系 —— 学习项目刻意为之
