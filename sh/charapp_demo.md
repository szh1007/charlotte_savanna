# CharApp 演示剧本

> 对应票据 `.scratch/Charlotte/issues/C04-demo-rig.md`。装置是 `sh/charapp_demo.sh`，
> 剧本是下面第四节那张表 —— 目标：**60–90 秒**内走完一条同时展示三件事的路径
> （工具调用真实 / HITL 真实 / 副作用真实）。

---

## 一、一条命令

```bash
bash sh/charapp_demo.sh              # 起全套 + 打开客服页
bash sh/charapp_demo.sh --no-open    # 只想把服务拉起来 (不开浏览器)
```

它依次做六件事：**前置检查**（MySQL / Redis / Postgres 真连一次，不只看端口）→
**建表检查**（`alembic upgrade head`）→ **起两个服务**（Django 8000 / 客服服务 1007，
后台 + 日志落 `logs/`）→ **健康检查**（轮询到真的应答为止，超时 60s）→
**演示数据准备**（幂等，见第三节）→ **打开客服页**。

- 服务已经在跑就**复用不重启**（跑第二遍不会撞端口），是不是本轮起的写在输出里。
- 依赖没起全时**直接退出**，每个依赖给一句能照着做的话（不是堆栈）。
- 服务起不来时摊出日志最后 20 行 + 常见原因（令牌没配 / 密钥没配）。

**冷启动实测**（2026-10-03，本机）：

| 情形 | 从执行脚本到能提问 |
|---|---|
| 服务都没起（脚本自己拉起来） | **14 秒** |
| 服务已在跑（复用） | **6–7 秒** |

→ 结论：**不用提前把服务开着**，当场起 14 秒，面试里说一句「稍等十几秒」就过去了。

停掉它们：`bash sh/_status_.sh` 看 PID，再 `taskkill //F //T //PID <pid>`。

## 三、数据准备（每次开演前自动跑，幂等）

`sh/charapp_demo.sh` 第 5 步跑的是：

```bash
python manage.py demo_prepare --user-id 10        # 可加 --balance-floor 2000 改下限
```

做两件事，各对应剧本里一种「跑完一轮就没了」：

1. **保证有一笔未付款订单**（代付那一步的标的）—— 已有就复用（取**最新**的那笔），不新建。
   报最新的那笔是有意的：剧本第二句说「最近的那笔待付款」，助手照订单列表挑中的就是它 ——
   脚本打出来的订单号因此对得上演示真正付掉的那一笔。
2. **保证余额不低于下限**（默认 1000）—— 够就不动。

两次执行的差别只写在输出里（第一次补了、第二次没补），买家看得见的几个数
（余额 / 未付款订单号 / 库存）一模一样 —— 所以**每轮演示前跑一次**就行，不用记状态。
输出最后那句「当前: 余额 …」才是**动手之后**的准数，前面那句是过程。

它**不碰**的东西：不建账号、不改密码、不删任何订单（历史订单正是「查的是真库」的素材）、
不动已有的收货地址。只有买家**一个都没有**时才补两样：没有 `Profile` 就按余额下限建一个，
没有收货地址就建一条占位地址（收货人写着「演示收货人」，一眼认得出）。

## 四、演示剧本（60–90 秒）

| 步 | 你说什么 | 演示什么 | 秒 |
|---|---|---|---|
| 1 | 「我的订单到哪了」 | 工具调用 + **查的是真库**（订单号是真的） | ~15 |
| 2 | 「帮我把**最近的那笔待付款**订单付了」 | **挂起卡**弹出（只有密码框） | ~10 |
| 3 | 本人输密码 → 点确认 | 密码**不进模型**（可当场说） | ~10 |
| 4 | 订单变 `paid`、余额扣掉订单金额 | **副作用真的发生了** | ~15 |

**第 1 步**：助手调 `list_my_orders`，念出订单号与状态。
要展示的细节：订单号是 24 位真实单号，**不是编的**。

**第 2 步**：助手调 `pay_my_order`（schema 里**没有**密码字段），框架在工具执行前挂起，
页面弹出确认卡。要展示的细节：**卡是页面弹的，不是模型在对话里问一句**。

> **措辞有讲究（2026-10-03 真机）**：光说「帮我把这单付了」，若账上不止一笔待付款，
> 助手会**反问是哪一笔**（它不猜）—— 这是好事，但演示里会多耗十几秒。所以第二句
> 直接说「最近的那笔待付款」；再稳一点就把 `demo_prepare` 打出来的订单号念出来
> （那正是助手会挑中的那一笔，见第三节）。

**第 3 步**：本人输六位支付密码。要展示的细节：密码走**一次性载荷**，不进模型上下文、
不进工具参数、不进日志（ADR-0015）。

**第 4 步**：订单变 `paid`，余额减掉订单金额（演示单是 99.00 元的那笔 —— 具体数字以
`demo_prepare` 打出来的为准；2026-10-03 走通那一轮实测 19505.00 → 19406.00，助手当场
报出付后余额）。要展示的细节：**钱真的动了**，不是话术。

### 每段的兜底动作（模型慢 / 抖动 / 上游超时的时候这么接）

| 步 | 翻车的样子 | 兜底 |
|---|---|---|
| 1 | 模型慢或没调工具 | 换问法「列一下我的订单」；再不行切终端入口：`bash sh/charapp_client.sh --user-id 10 -q "我的订单到哪了"` —— 同一套服务、同一个工具，**反而是更好的证据**（两个入口共用一处装配） |
| 2 | 确认卡没弹（助手只说「已付」） | 刷新页面（会话编号在 `sessionStorage`，刷新后还在同一段对话）；重问一次并带上订单号：「把订单 `2026…` 付了」；助手反问「哪一笔」也照报 |
| 3 | 确认后说「没成功」 | **不会扣钱**：业务端点当场拒（Django 请求日志里那一条 `…/pay/ 400`），助手如实说「没有成功，订单还是待付款」。值不对（位数不对或对不上）都走这一条 —— 重说一次就能再输一遍（2026-10-03 实际撞过一次，当时只记到 400 + 订单仍 pending，具体是哪种值不对没有取证） |
| 3 | 该说却没说清的 | 密码由**本人**输 —— 助手不该、也不会向你要密码；这条本身就是可以讲的点（ADR-0015） |
| 4 | 想确认副作用 | 页面看余额与订单状态；更硬的证据是库：`python manage.py shell -v 0 -c "from app.minimall.models import Order; o=Order.objects.get(order_no='<单号>'); print(o.status, o.paid_at)"` |
| 任意 | 网络抖动 / 上游超时 | 重试一次是**安全**的：代付那一步有幂等键与「已付过的单不重复扣款」两道闸，重复请求会被拒而不是扣两次 |

**腾讯会议共享桌面时等待会被放大**：真等超过 ~20 秒就切兜底，别干等。
