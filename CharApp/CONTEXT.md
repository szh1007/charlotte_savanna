# CharApp — 电商智能客服

基于 `CharAgent` 通用 agent 框架构建的业务应用集合。当前只有一个上下文 `minimall` (包 `CharApp/minimall/`), 对接 `app/minimall` 的商城数据。

## Language

### 售后域（AfterSale）

**退款（Refund）**：
钱退回买家，不涉及货物寄回。`RefundRequest` 只表达退款。
**是否回滚库存以发货为界**：货还没出去就回滚，出去了就不回滚 —— 与走取消还是走退款无关。
_Avoid_：售后、退货 —— 三者含义不同，不可互换

**退货退款（Return & Refund）**：
货物寄回并经卖家签收后，钱才退回买家。需要退货地址、承运商、物流单号。
_Avoid_：退款 —— 本项目未实现退货退款，且 minimall 无任何物流字段

**售后（AfterSale）**：
退款、退货退款、换货、维修的上位概念。
_Avoid_：客服、工单 —— 本项目只用它作域名词（命名空间），不建对应模型

**投诉（Complaint）**：
买家对商品或服务不满的表达，不涉及资金流转。
**不实施**（2026-09-21 决定）—— 保留此词只为消歧：它不是售后、也不是退款。
_Avoid_：售后 —— 投诉与退款无状态耦合，是两个独立模型

### 角色

**买家（Buyer）**：
持有 `django.contrib.auth.User` 的注册用户，通过 `Profile` 持有余额，是唯一能发起下单与退款的角色。
_Avoid_：用户、客户

**管理员（Staff）**：
`User.is_staff=True` 的账号，只能在 Django Admin 中操作（含审批退款、发货）。
_Avoid_：卖家、商家 —— **本项目不存在卖家角色**，不得假设其存在

### 交易

**余额（Balance）**：
`Profile.balance`，买家预存的可支付金额，注册时赠送 10000。支付与充值都只在此字段上增减。
_Avoid_：钱包、账户余额

**支付密码（Payment Password）**：
6 位数字，与登录密码分离，仅在支付与充值时校验。
**助手不代付**（2026-09-21 决定）—— 校验需要明文经手，与「身份不进工具参数表」不可调和；
若要代付，正确做法是让用户在页面上**本人**输入，属 L3 的框架级挂起。
_Avoid_：交易密码

**取消（Cancel）**：
买家单方终止订单。**只有未付款（`pending`）能取消**；付款之后一律走退款。
取消即刻生效、回滚库存。
_Avoid_：退款 —— 取消不需要审批，退款需要

**退款申请（RefundRequest）**：
买家对已支付订单发起的退款请求。状态机 `requested → approved → refunded`，或 `requested → rejected`。
**退多少由管理员在批准时定**（协商金额，不超过订单总额）；买家申请时不带金额。
同一订单同一时刻只允许一个进行中的申请；被驳回后可以再提。
**要不要回滚库存看申请时发没发货**（见「退款」词条）；退款流程进行中的订单不允许发货。
_Avoid_：退款单、售后单

**退款中（Refunding）**：
订单在退款流程进行中的状态。申请退款即进入，打款后变「已退款」，被驳回则**恢复申请前的状态**。
_Avoid_：申请中、处理中 —— 它描述的是**订单**的状态，不是退款申请的状态（后者叫 `requested`）

### 集成

**内部端点（Agent Endpoint）**：
`app/minimall/views_agent.py` 暴露给 CharApp 的粗粒度业务动作，以 `X-Internal-Token` 认证。
_Avoid_：管理 API、内部 API —— 它是「面向 agent 的业务动作」，不是用户面接口的镜像

**CharAgent**：
通用 agent 框架，对业务零知识 —— 不 import 任何 `CharApp` / Django / minimall 代码。
_Avoid_：把业务代码放进 CharAgent

**CharApp**：
基于 CharAgent 构建的业务应用。依赖方向严格单向 `CharApp → CharAgent`。

### 会话运行时（Chat Runtime）

**会话（Conversation）**：
一段连续的对话，也是数据隔离与快照分区的最小单位。
框架侧叫 `thread`（`thread_id`），业务侧叫 `conversation_id`，前端叫「对话框」—— 三处指的是同一个东西。
_Avoid_：进程、连接 —— 会话的生命周期与任何进程无关（进程重启后它还在）

**运行（Run）**：
会话里的一次问答：从一次提问，到一次答复终止。
**预算、护栏、成本都按运行算**（写操作上限、token 预算、耗时上限），所以「这一次」与「这一整段」要分清。
_Avoid_：会话 —— 「会话级预算」与「运行级预算」不是同一件事

**快照（Checkpoint）**：
会话的**账本**：每一轮落一帧、只追加不改写，用来断点续跑与回溯。
它记的是**给模型看**的那份消息（含工具往返与推理链），不是给人看的。
**身份说明按引用记**（名字 + 正文哈希），正文的唯一定义在提示词文件里 —— 配置不逐帧抄。
_Avoid_：记录 —— 两者形状与用途都不同（见下条）

**记录（Transcript）**：
会话的**给人看的**版本：一条消息一行，每行标着要不要展示给前端。
**只有它永不压缩** —— 用户刷新后看到的、在左侧列表点开的那份，就是它。
_Avoid_：快照 —— 它是给模型的**全量账本**（只追加不改写），压缩动的是「上下文视图」，账本与记录两份都不动（见 ADR-0008）

**身份说明（Identity Prompt）**：
会话历史第 0 条 `role: system` 消息，说明「你是谁」—— 由提示词文件（一版一个文件）渲染而来。
**模型对自己的身份没有内省能力**，这条不给就会从语料里续写一个最像的，所以必须由会话给。
_Avoid_：系统提示词 —— 框架里「提示词」指文件本身（还有摘要指令、工具描述等），身份说明只是其中一份

**上下文视图（Context View）**：
这次运行**实际发给模型**的那份消息：身份说明 + 压缩摘要 + 最近若干轮完整对话。
它与账本（快照）**不是同一份**：越聊越短的是它，账本一直长。
**它的第 0 条就是账本的第 0 条**，所以「身份说明按引用记」这条规矩对两份都成立（记的是同一个引用）。
**压缩摘要（Summary）**：上下文视图里替代「更早那些轮」的那条消息，由模型自己生成、滚动更新。
**压缩降级（Compaction Fallback）**：摘要没能生成出来时，这一轮**不切刀** —— 一条消息都不丢，退到「只投影」。摘要失败不算压缩失败，只是「这一次压得不狠」。
**紧急压缩（Emergency Compaction）**：上游明确说输入超出窗口时才走的那一档 —— 不问阈值也不问水位线，裁到只剩最近一个提问。**它是整条链路上唯一「允许丢信息」的地方**：丢掉的段在账本里记成「有意放弃」。平时的压缩只丢「已经进过摘要」的那段。
_Avoid_：把上下文视图当成「历史」—— 用户看到的历史（记录）永远比它全
_Avoid_：把「压缩」一律读成「丢信息」—— 平时那道只丢已经压进摘要的，真正会丢的只有紧急那一档

**置顶（Pin）**：
用户把一段会话钉在列表最前，**最近钉的排在更前面**。
记的是**时刻**（`pinned_at`）不是布尔：布尔说不清「谁先钉的」，而排序要靠这个。
_Avoid_：把置顶当成"收藏"—— 它只影响列表顺序，不改会话本身任何东西

**删除（Delete，软删）**：
用户语义上的「删除」= **从我的列表里消失**；数据一条不动（行、消息、运行、快照都还在）。
**这是有意的**：运行表上挂着成本记账、快照里是「模型为什么忘了」的唯一线索，真删会把它们一起带走（外键 CASCADE）。
_Avoid_：把「删除」当成「数据没了」—— 库里查得到，只是不再列出来；真删是将来某个清理动作的事，本阶段不做

**会话搜索（Conversation Search）**：
在会话列表里按**标题**找一段对话：大小写不敏感，`%` 与 `_` 按字面当字符，只在当前
(租户, 买家) **还看得见**的会话里找（删掉的不算）。
**只搜标题，不搜消息正文**（2026-09-23 决定，见 ADR-0010）—— 搜出来的每一条，标题上
都看得见那个词。搜的是**完整标题**（上限 100），不是列表上截到 20 字那一行，所以
「搜到了、而那一行的可见部分里没有这个词」是正常的。
_Avoid_：消息搜索 —— 一个答「哪段对话」、一个答「哪句话」；把正文卷进会话搜索，就得
连相关性排序与命中位置一起做（否则顺序说不通），那是另一个量级的功能
