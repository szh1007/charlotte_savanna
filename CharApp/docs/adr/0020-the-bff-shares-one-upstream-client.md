# BFF 与客服服务之间共用一个进程级 HTTP 客户端；这条链路因此依赖单进程部署

**Status:** accepted（2026-09-25）

## 决定

`app/minimall/views_bff.py` 里三条转发路径（问答开流 / 五个短请求 / 取消）**共用一个
模块级 `httpx.Client`**，进程退出时由 `atexit` 关掉：

1. **共享一个客户端**（`_CLIENT` + `Limits(max_connections=10, max_keepalive_connections=10)`），
   不再每次请求新建一个；
2. **超时逐次传**（`timeout=` 在调用点给，客户端上**不设**默认值）—— 三条路耐心不同
   （问答 120 秒 / 短请求 10 秒 / 取消 10 秒），客户端上那份默认值一旦被谁当成兜底依赖上，
   「取消只等十秒」就悄悄没了；
3. **不做重发**：复用带来的唯一新失败面是「请求恰好落在上游咽气的那一瞬」，而那一瞬
   上游正不在，重发换来的还是同一句「联系不上」——多一层代码、多一种「到底发了几次」的
   疑问，换不来用户能看见的差别。

**前提是部署为单进程**：`atexit` 要在进程收尾时可靠地跑。这条前提不是本片引的，出处是
`CharAgent/server/sessions.py` 的「单进程」一节（`SessionRegistry` 与 `RunRegistry` 都在
进程内）——与框架侧**同源**，不是新引入的假设。

## 为什么需要它

改之前每次转发都新建一个客户端，本机实测 **690 ~ 970 ms**（~690 ms 那一头是 issue 25 的
真机观测 —— 用户看到的那一下「横幅先蹦一下」就是它；六条路径的整张表在 issue 30）。这笔钱
花在哪儿是量出来的，不是猜的：

- `httpx.Client.__init__` 要为「主传输 + 两个代理传输」各建一个 SSL 上下文；
- `ssl.create_default_context()` 里的 `load_verify_locations`（读系统证书库）本机一次约
  **310 ms**，三次就是 ~930 ms；
- 而上游是 `http://127.0.0.1:1007`，那些 SSL 上下文**一次都用不上**。

改后同一批操作落到**十几毫秒**：issue 30 当天实测 **2 ~ 16 ms**（六条路径的中位数 / 最小），
收口当天（2026-09-25，整套服务都开着）拿同一支脚本重跑是 **15.1 ~ 17.3 ms 中位数 /
3.0 ~ 14.5 ms 最小** —— 两次的差别来自机器当时的负载，量级一致。

## 代价与边界

- **池子额度是固定的 10 条**：页面同一时刻只跑一个运行（`finished` 那道门管着），十倍余量
  足够。真被占满的代价是那条请求在池子上等 `pool` 超时，而不是立刻回话。
- **上游重启后池子里那条闲置连接可能已经死了** —— 这条**httpx 自己认得出**：httpcore 判
  一条闲置连接还能不能用时，除了 keepalive 到点，还会看那个 socket 是不是已经「可读」
  （对面关了连接才有这个状态，`http11.py` 的 `server_disconnected`），认出来就换一条新的。
  本机实测：上游杀掉再起回来，下一次请求走的就是新连接，用户看不到任何异常。真正漏得过去
  的只有「请求恰好落在上游咽气的那一瞬」，见「决定」第 3 条。
- **共用的客户端带着那一刻的代理设置**：本机实测 `http://127.0.0.1:1007` 也被发去系统代理
  （`trust_env=True` 默认读 `getproxies()`，本机是 `127.0.0.1:7890`）。这**不是共享引入的**
  （改前每次新建也走同一个代理），但它是这条链路上一个隐藏的跳数 —— 记账 issue 31 的欠账表，
  本片不动它。

## 考虑过的替代方案

- **每次请求新建**（改前的写法）：行为正确，但每次付 ~930 ms，而且这笔钱落在**首字之前** ——
  用户先看到一次空转。
- **流式那条单独留一个客户端**：票据里留过的第二个选项。实测不需要（并发上界本来就小），
  而两个客户端会让「关闭路径」从一个变两个 —— 少一个能写错的地方。
- **给可安全重发的五条路各加一次重发**：写完又撤了，理由见「决定」第 3 条。量下来它**没有任何
  用户能看见的差别**，按「别为了兑现规划去改一个不划算的东西」撤掉，只把实测写进代码注释。

## 什么时候该重新看这条决定

- **部署不再是单进程**（多 worker / 多机）→ 共享的正当性（`atexit` 可靠）与连接额度都要重算；
- **上游地址不再是本机回环**（跨机调用）→ 连接池参数、代理绕行、失败面三样都变。
