# 内部端点直接采信调用方声明的 X-User-Id

**Status:** accepted（2026-09-19）

## 决定

助手服务调商城的内部端点时，请求头带两样东西：`X-Internal-Token` 证明「我是内部服务」，`X-User-Id` 声明「我在替哪个用户办事」。商城**直接采信这个声明**——不签名、不校验、不与任何会话核对。换句话说：**谁拿到内部令牌，谁就能冒充任意用户。**

内部令牌本身沿用本仓已有的做法（`app/charplot` 的 `X-Internal-Token`，常量时间比较，未配置令牌时拒绝一切请求）。

同一条做法同时用在本项目的**两条**服务间边界上：Django ↔ 助手服务、助手服务 ↔ 商城接口。两条都是同一信任域内的调用，做法与取舍完全一样，所以记一条 ADR 就够——分开写会变成同一件事记两遍。

## 身份是从哪来的（这条决定成立的前提）

`X-User-Id` 这个值**不是用户给的**，它有一条完整的来路，而这条路上只有一个环节真的验证了身份：

```
浏览器登录（session cookie  ←── 唯一真正验证「你是谁」的地方）
    ↓  Django 从已认证的会话里取出 user_id
X-User-Id（服务间转发）
    ↓  助手服务放进运行上下文
RunContext.payload
    ↓  工具装配时裹进闭包
模型看不见、也改不了它
```

第一阶段的命令行版本把起点换成 `--user-id` 参数（本机演示，没有浏览器可登录），除此之外这条链一字不差。

**所以「为什么敢信一个裸声明」的答案是：这个值由已认证的一方取出并转发，全程不离开同一个信任域。** 一旦这个前提不成立——值来自域外，或者转发链上有一段不受信——整条论证立刻作废。

顺带说清一个容易混的点：**用户数增加并不改变这个威胁**。第二阶段的网页版即使多个买家同时在用，`user_id` 仍由 Django 从各自的会话里取出，买家没有机会填别人的值。真正的威胁只有一个——内部令牌泄露——它在单用户时就存在，只是当下不值得为它做工程。

## 为什么这么选

第一阶段只有本机单用户演示，助手与商城跑在同一台机器、同一个信任域里。为了这个形态引入令牌签发 / 验签 / 时钟偏移 / 密钥轮换，是在**为一个不存在的威胁做工程**——而且这些机制的复杂度会盖过本阶段真正要验证的东西（框架能不能接住一个真实业务）。

## 代价（必须说清，否则这条 ADR 就是自我辩护）

这个决定把「内部令牌泄露」的爆炸半径从「能读商城数据」扩大到「能读**任意用户**的数据」。本机演示里无所谓，但只要部署形态一变（跨机、独立部署、走公网），它立刻不可接受。

它**不是**被遗忘的漏洞，是**记在案的欠账**——写上生产化路径就是为了让它可还。

## 什么时候必须还

判据是**信任域有没有被拆开**，不是用户数：一旦助手服务与商城不再同机同域（独立部署、跨机、走公网），或者内部令牌会离开当前这个域，裸声明就从「演示简化」变成「真漏洞」。

按本项目的里程碑说：L1a 命令行（`--user-id`）与 L1b 网页版都在单机单域内，可以继续用这套；**触发点在把助手服务部署出去的那一刻**。

## 生产化路径

**「谁在验证用户」这件事不变**——仍然是浏览器那边的会话 cookie，仍然只有一个验证点。要换的只是 `user_id` 从 Django 到助手服务、再到商城这一段**怎么传**：

- **内部 JWT**：Django 签发短期令牌，把 user_id 放进 `sub` claim，助手与商城用公钥验签。接收方只信签名，不信任何裸声明。
- 更严的一档是 **mTLS + 服务网格身份**——让「我是谁」由传输层证明，而不是由请求体自报。

届时要改的是**认证契约本身**：两条服务间边界上每个端点的取用户方式都要改。当前规模：商城侧 9 个只读端点（`app/minimall/views_agent.py`），第二阶段加写接口后会更多；Django ↔ 助手服务那条边界同理。所以这是一次跨所有接口的迁移。

这正是它值得记一条 ADR 的原因——它难以回退，没有上下文时反直觉，且确实存在取舍。

## 考虑过的替代方案

- **把身份做成工具参数（让模型自己说"查谁"）** —— 否。工具的参数表会被序列化成文本发给模型看，身份一旦成了参数，模型就看得见，也可能被诱导填别人的值。现在的做法让这条路径**根本不存在**：模型不知道有这么个东西（PRD §4.2）。
- **现在就上内部 JWT** —— 否。第一阶段没有第二个信任域，签名验签纯属空转；而且真要跨域部署时，密钥管理方案得按那时的部署形态才能定，现在定的八成要重来。
- **每个端点各自写一遍令牌校验** —— 否。9 个端点抄 9 遍同一份契约，改一次要改 9 处，迟早漂。
