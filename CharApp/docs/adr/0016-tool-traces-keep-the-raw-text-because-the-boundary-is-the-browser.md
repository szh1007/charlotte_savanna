# 工具轨迹落库保留原文：ADR-0003 的边界是浏览器，不是存储

**Status:** accepted（2026-09-24）

## 决定

L3 的工具调用轨迹（`charagent_tool_calls` 的 `arguments` / `result`）**保留模型给的参数原文与工具的返回原文**，不做入库前脱敏。订单号、地址、余额会进 PG。

同时**澄清 ADR-0003 那句「工具参数原文与返回正文不出本进程」**：它的真实含义是「**不出到浏览器**」。原句是 `redaction.py` 的落点描述（业务包装 `event_sink`，把 `tool_call` / `tool_result` 两个事件的载荷换成一句人话），它管的是**展示层**；本 ADR 管的是**存储层**。两条一起看才是完整的脱敏故事：

| 层 | 装什么 | 谁管 |
|----|--------|------|
| 展示（浏览器看到的帧） | 只有 `label`（"正在查询订单"） | ADR-0003，`CharApp/minimall/redaction.py` |
| 存储（PG 里的轨迹与帧） | 原文（订单号、地址、余额） | 本 ADR |

## 为什么存储层要留原文

**轨迹的用途就是回放与归因，脱了就不叫证据。** L3 那句验收标准是"能回答**当时它看到了什么**" —— 如果 `result` 里的订单号被打成 `138****`，回放时看到的是一个模型**从来没有**看到过的世界，那这个工具就答不准它唯一要答的问题。DESIGN #59 说得更直白：agent 有随机性，**调试靠 trace 而非复现** —— 而 trace 的价值全在原文。

而且这不是新开的口子：**帧里早就有了**。`metadata.view`（issue 22）存的就是「这一轮真的发出去的那份」，而 `state`（进度）存的是完整账本 —— 工具返回的正文本来就在快照里，一个字没少。本 ADR 只是让轨迹与它们口径一致，而不是让 PG 里第一次出现原文（**它已经在了**）。

## 代价：说清，否则这条 ADR 就是自我辩护

**PG 里现在有用户原文，而"删除"是软删（ADR-0007）。** 用户点了"删除会话"，行、消息、运行、快照、轨迹**一条都不动**，只是不再列出来。两份 ADR 合起来的结论是：**用户以为删掉的东西，库里查得到，而且现在比之前多了一个面（轨迹）。**

这条代价**认下来**，理由有三：

1. **ADR-0007 那条软删本来就是这个后果**，当时记的理由（"运行表上挂着成本记账、快照里是「模型为什么忘了」的唯一线索，真删会把它们一起带走"）对轨迹同样成立，且更强 —— 轨迹是审计材料。
2. **"真删"是另一个量级的功能**：物理删除 + 级联衍生数据（向量 / 快照 / 轨迹）+ **能证明已删**，这是 DESIGN #28「数据合规删除权」（P2，至今未做）。把它塞进 L3 会让 L3 的主题（挂起与观测）被一个合规域盖住。
3. **它是真实的讲述素材，不是要藏的短板。** 面试官问"你这套东西合规吗"，正确答案不是"我做了脱敏"，而是"**我知道哪一层该脱敏、哪一层必须留原文，也知道软删在这里意味着什么，以及它变成合规缺口的确切位置**"。现在这条 ADR 就是那个答案。

## 与 ADR-0003 的关系（它不是推翻）

ADR-0003 的「不留演示开关」、`reasoning` 与 `final` 照旧出去、以及"这条保证的范围（2026-09-22 补记）"那一段，**全部继续有效，一个字不改**。本 ADR 只做一件事：把它那句容易被读成"存储层承诺"的话，钉回它的真实范围（展示层）。

`reasoning` 那一行的理由在本 ADR 下更清楚了：ADR-0003 说"遮掉它会让 L3 的『当时它看到了什么』不可解释" —— 那句话当时就是**指着 L3 说的**，本 ADR 是来兑现它的。

## 考虑过的替代方案

| 方案 | 为什么否掉 |
|------|-----------|
| 入库前脱敏（`result` 里的订单号、地址打码） | 轨迹从此**不可信**：回放看到的是打码后的世界，而"模型当时看到的是原文" —— 用它调试会得出错误结论。脱敏保证的"库里没有敏感值"换来的是"工具答不准它唯一要答的问题" |
| 加 TTL / 保留期 | 方向对，但它是另一件事（保留策略，不是脱敏），且 issue 26 已把「帧保留期策略」列为待定 —— 两者口径必须一起定（视图那份与轨迹那份指向同一次运行，不能一个留一个删）。**不做，不是漏了** |
| 轨迹只记 `arguments` 不记 `result` | 拆开看没有道理：`arguments` 里同样有订单号与地址（"当时它看到了什么"里模型自己填的那一半）。要脱就两边都得脱，要留就两边都留 |
| 存摘要不存原文 | 摘要要生成（多一次模型调用、多一份成本、多一个失败路径），而它答的还是同一个问题 —— 只是答得更糊 |

## 什么时候该重新看这条决定

- **若 #28「数据合规删除权」开始做**：那时"真删"要级联到 `charagent_tool_calls`，本 ADR 的代价那一节要重写，且两条 ADR 要一起改。
- **若帧的保留期策略落地**（issue 26 记的待定项）：轨迹与帧的保留口径必须同进同退。
- **若这套东西真的接了外部用户**：那时"库里有没有原文"从"讲述素材"变成"合规问题"，本 ADR 从 P2 待办升格为必做前置。
