# 身份说明只存引用不进帧正文；成本用归因列回答，不从总量里减

**Status:** accepted（2026-09-23）

## 决定

两件事一起定，因为它们同出一个疑问（「系统提示词把用户的 token 消耗撑大了」）：

1. **帧 v5：身份说明的正文不再进快照**。帧里只留一个引用 `{"name": ..., "sha256": ...}`（`CharAgent/prompt/ref.py`），正文按版本留在盘上（`prompt/system/vN.prompt`）。写侧由**造帧的人**摘掉（`detach_identity`，loop 落帧时调）；读侧由**会话层**补回（`restore_identity`，`_hydrate_once` / `_reclaim_progress` / `_restore` 三处）。老帧（`prompt_ref=None`）保持内联，仍然完全自描述。
2. **成本只加归因，不改账**：`charagent_runs` 新增 5 列用量分解（`input_tokens` / `output_tokens` / `reasoning_tokens` / `cache_hit_tokens` / `cache_miss_tokens`，**全部可空**），`total_tokens` 与 `LoopGuard` 的 token 预算**一个字不改**；顺手填上一直空着的 `prompt_version`。

## 为什么需要它：最初那两条里，第二条被否掉了

原始诉求是「系统提示词不入库快照」+「每次模型计算的 token 减掉系统提示词那部分」。第一条成立，**第二条否掉**：

- **`total_tokens` 是账单，不是指标。** 它是唯一能跟供应商对账的数，也是 `LoopGuard` 那 6 万 token 硬刹车的输入。从它里面减掉一部分，刹车会放行比它以为的更多的真实花费 —— 偏向不安全一侧。
- **减出来的数会撒谎。** deepseek-flash 的缓存命中输入单价是未命中输入的 1/50、输出价的 1/200。实测口径下：系统提示词在**第 2 轮起**占 token 数的 ~47%，占**钱**的 ~2%。按 token 减，报表会显示「省了 47%」，而实际省下的是 2% —— 一个把 2% 说成 47% 的指标比没有指标更糟。
- **它还不完整。** 同一份「每轮重发的固定前缀」里还有 17 个工具 schema（实测约 3600 token，比提示词那 2600 还大）。只减提示词、不减工具 schema，这条规则是任意划的。

于是改成：**原始分量入库，口径在查询侧派生**。要「用户可归因用量」就 `input + output` 里减去固定前缀的估算；要算钱就按三档单价分别乘 —— 都由那 5 列加 `prompt_ref` 算得出来，不需要在写入路径上做减法。

第一条为什么值得做（**理由不是省空间**）：同一段会话的每帧抄的都是同一份几千字配置，但它只占快照总存储的 ~1/N（N = 轮数）—— 真正在重复的是「每帧存一份全量账本」那件事（O(N²)）。所以这条的价值在于**把「帧里装什么」说清楚**：帧里装的是**对话**，配置按引用记。这与 `CONTEXT.md` 的「上下文视图」词条一致 —— 系统提示本来就属于视图侧，不属于账本。附带得到一个能力：`runs.prompt_version` 从建表起一直空着，现在有值了，「这一轮是哪版提示词答的」可查（#40）。

## 代价与边界

- **帧不再完全自描述**：读一帧需要盘上那份提示词。同一版本的文件在 → 逐字还原；被**就地改过** → 用当前那份继续 + 一条 warning（不阻断、但留痕）；**被删掉** → 抛错，不猜也不退回上一版。老帧（v4 及更早）不受影响，它们的正文就在帧里。
- **「续聊用哪一版」有明确答案：用帧里记的那一版。** 换了默认版本不影响进行中的会话（历史保真，前缀缓存也不会中途跳）；只有新开的会话用新版。补回正文时引用会**按实际用的那份重算**，于是「换过版本之后接着聊」不会在下一次落盘时被哈希校验拦下。
- **漏了补的那一步是无声故障**：模型少一条人设，不报错，只是答得不像那个人。所以 `AgentLoop.resume` 加了一道护栏 —— 帧声明了引用而历史里没有身份说明时当场 `LoopConfigError`。
- **摘的动作放在造帧这一步**（loop 的 `_save_checkpoint`），不放编解码器：内存版后端不编码，放编码器会让「帧里存不存正文」随后端而变，违反「换存储不换行为」。

## 考虑过的替代方案

| 方案 | 为什么否掉 |
|------|-----------|
| 从 `total_tokens` 里减掉提示词（原提案） | 污染账单与硬刹车；把 2% 的钱说成 47% 的省 |
| 提示词彻底移出账本，loop 持有「固定前缀」（LangGraph `instructions` 那种） | 领域模型更纯，但要动压缩策略的三条不变量、anchor 的消息计数、会话装配 —— 改动面大 5~10 倍，换来的只有「术语更正」这一点。**它是本方案的超集**：将来升级只需再动 loop 内部，帧格式不用再改一次（`prompt_ref` 已经是它要的形状） |
| 帧里保留一条 `content` 为空的**占位** system 消息 | 忘了还原时上游可能拒（好）也可能当成「没有身份说明」收下（坏）—— 失败模式不可预测 |
| 在**编解码器**里摘正文（最初的实现） | 内存版后端不编码，三个后端会存出两种形状。这个错是被一条会话级用例当场抓出来的 |
| 顺手把 `total_cost` 也算了 | 单价会变（官方 2026 年内改过价目表与模型名）。不把价格写进运行路径，留到 L3 |
| 迁移函数把老帧的第 0 条正文**提取成引用** | 提出来只能标「版本未知」，还原时还得猜；不提则老帧**完全自描述**，零损失。于是迁移只补默认值 |

## 什么时候该重新看这条决定

- **若「提示词文件被删」那条路真的发生过**：把「按 sha 找回版本」做成正式能力 —— 一版一个文件的布局已经为它准备好了。
- **若这 5 列开始被用来算钱**：先把三档单价做成配置项（L3 的成本记账片）。
- **若要做「固定前缀」的显式归因**（工具 schema 那 3600 token）：那正是 L4 的「工具数量 A/B（17 全挂 vs 动态裁剪）」要回答的问题，答案在那里，不在这里。
- **若压缩策略的阈值要调**：注意被压缩掉的旧历史本来可能是缓存命中价（近乎免费），压掉它反而要按未命中价重付一次新前缀。压缩的理由是窗口与首字延迟，**不是省钱**。
