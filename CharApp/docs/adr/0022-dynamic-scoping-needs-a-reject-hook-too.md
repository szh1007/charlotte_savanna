# 按题裁剪工具要配一个「拒绝」钩子：可见集与可调用集必须等价

**Status:** accepted（2026-09-29）

## 决定

「按场景动态裁剪」（`CharApp/minimall/scoping.py`）落在**业务侧的两个钩子**上，而不是
把它正式化进框架：

1. `BEFORE_TURN` 上**原地**把当轮那份 `tools` 列表缩到本次范围内的工具（`tools[:] = ...`）；
2. `BEFORE_TOOL_EXECUTE` 上再挂一条**拒绝**：调用的工具不在范围内就 `Decision.reject`，
   理由与护栏那句明显不同（「不在这次能用的范围里」 vs 「这一单超了 5000」）。

**两条必须一起装**，而且**生产入口一条都不装**（`session_for(scope=None)`，CLI 与
server 给的都是 None）—— 这是**实验装置**，不是产品功能。

## 为什么需要它

**只裁不拒是假的。** `BEFORE_TURN` 拿到的 `tools` 是**活引用**、原地改当轮就生效 ——
看起来「收窄了可见集就禁用了工具」。但**执行查的是另一本账**：框架的
`AgentLoop._tool_map`（组装会话时就建好了）。只裁不拒的后果是模型仍调得到被裁掉的
工具，「两组」比的就不是「少给」而是「看不见」 —— 那次 A/B 的结论当场作废。

**「两组可调用集等价」是 A/B 成立的地基**：自变量的差必须只有「给哪些工具」，不能混进
「能不能兜底调回来」。这一条在代码里看得见：`tests/test_scoping.py` 里有一组四行组合表
（裁 / 拒 × 护栏 / 范围）逐行钉住，另有一条端到端用例断「被裁掉的那一调**压根没打到
商城**」（假商城那条路由 `called is False`）。

**为什么放业务侧而不是进框架**：进框架等于承诺「禁用工具」是一等能力，而那时还没有
任何数据说明值得 —— 数据来了（L4 的工具数量 A/B）：裁剪买到的是 **token（−35%~38%）**，
准确率的差落在噪声里。所以它作为框架能力的理由**没有**成立，留在业务侧当实验装置
（`python -m CharApp.eval.run` 那条线）是对的。

## 代价与边界

- **被裁掉的写工具照样会碰护栏的账本**：框架的 `decide()` 会问**每一个**插件，所以
  一次被裁掉的 `place_order` 会先经过范围钩子（拒绝），而护栏那边也看得到它。
  组合表把这一条写成了用例，而不是靠「应该不会」。
- **顺序只决定一件事**：两条钩子**都是拒绝**时，先到的那句理由说了算。范围装在护栏
  **之前**，于是一个被裁掉的超预算 `place_order` 听到的是「这工具不在范围里」（它压根
  没给模型），而不是「这一单超了 5000」。裁决本身与顺序无关（框架侧拒绝优先），
  所以这是**措辞**问题，不是正确性问题 —— 但它值得钉住（有一条端到端用例）。
- **分类器是规则，不是模型**：题面关键词 → 1~2 组工具，兜底 `product` + `account`。
  它一定会有分错的时候，于是报告里有一块**分类错误**（把「装置坏了的那几跑」单列，
  并给一份「只数分类正确」的分数）—— 否则那些跑次会被读成「模型答错了」。
- **挂起恢复那两段要用同一个范围对象**：范围是**一次运行**的属性，中途换一套可见集
  会让轨迹说不清（`subject.py` 里两处装配都传同一个 `self._scope`）。

## 考虑过的替代方案

- **只裁不拒**：已证否（见上），而且是这一条 ADR 存在的原因。
- **把「禁用工具」正式化进框架**（在 `ToolSpec` 或注册表上开一个 `disabled` 面）：
  等数据。数据出来了 —— 收益只有 token，而「少给工具能让模型选得更准」那条假设**没有**
  被证实（两趟都在噪声里）。给框架加一个语义面，换一个只在实验里用到的开关，不划算。
- **裁掉的不给模型看、但允许它调（只做提示）**：那两组比的是「提示强度」，而这次要问的
  是「工具多了会怎样」 —— 问题被换掉了。
- **按轮次动态裁**（第一轮给全集、之后收窄）：变量里会混进「什么时候裁的」，那次 A/B
  的结论就归因不到「给多少工具」上（题面一句话决定范围，是刻意的）。

## 什么时候该重新看这条决定

- **裁剪要进生产**（例如按买家角色给不同的工具集）→ 那时它该是**框架能力**：可见集与
  可调用集等价这件事必须由框架自己保证，而不是每个业务各挂两个钩子；
- **模型侧有了原生的工具选择机制**（例如上游支持的 tool groups / 命名空间）→ 那才是
  裁剪的正规落点，本片的两个钩子就成了一段历史；
- **分类器换成模型打分**：那时「分类错误」那一块的口径要重做（现在它假设分类是**确定性**
  的纯函数，同一道题每次分到同一组）。
