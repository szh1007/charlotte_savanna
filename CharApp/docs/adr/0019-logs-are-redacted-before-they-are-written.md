# 日志脱敏在写之前；访问日志整个关掉

**Status:** accepted（2026-09-25）

## 决定

四件事一起定，因为它们同出一个问题（**留痕里的用户数据怎么算**）：

1. **脱敏发生在「写之前」，名单归业务**：框架给 `Redactor` 协议（`redact_text` 认形状 /
   `redact_fields` 按字段名打）+ 四类跨业务形状的规则（手机号 11 位 / 邮箱 / 身份证 /
   银行卡），业务在装配处声明**自己哪些字段敏感**并把日志出口包一层
   （`CharApp/minimall/log_redaction.py`；出口是 `server.py` 的 `log_writer()`）。
   **命令行那条路不包**：它的出口是开发者自己的终端，不落盘（与 ADR-0003 给命令行
   `redact=False` 同一个理由）。
2. **CharApp 服务的 uvicorn 访问日志整个关掉**（`uvicorn_config` 里 `access_log=False`）：
   它记的是**整条 URL**，而列会话那条路的搜索词走查询串（`?q=`），它完全可能是一个订单号。
   前端特意把搜索词放进请求体（正是这个理由），到了这最后一跳没有别的形状可放。
3. **Django 那侧不再把上游响应正文写进日志**：上游拒绝时只记**状态码 + 错误码**
   （`_refusal_code` 取到的那一个），响应正文一个字符都不进日志；「记什么」收在一个函数里
   （`_log_refusal`，三条路共用），想把正文加回来得改那一处。那个「截 200 字符进日志」的帮助
   函数（`_detail`）随之删掉 —— 连同它那个截断常量（本片之后 Django 侧再没有一处「截上游内容
   进日志」；`_with_user_copy` 里「帧解析不了」那条也改成了只记帧长与失败原因）。
4. **认不出来的如实留着**：自由文本按形状认，不猜订单号那种「本项目自己发的编号」；
   声明成手机号但值不长那样的，一个字都不动（要「一定不留原文」就声明 `WIPE`）。
   **不加演示开关** —— ADR-0003 已否过一次（「演示时把敏感数据打开」的环境变量是安全反模式）。

## 为什么需要它

- **时机只有一个。** 日志一旦落盘就会进聚合 / 检索 / 备份 / 别人家的机器，事后擦不干净；
  写之前那一步是唯一的时机。这并不是「少记一点」，是记法的问题。
- **三个泄漏点都是实证的，不是假想的**（规划期核实）：搜索词进访问日志（URL 里的用户数据）、
  上游正文被截 200 字符写进日志（`_DETAIL_LIMIT` 的注释自己写着「只进日志」）、
  供应商错误正文顺着「异常 → 重试提示 → writer」进日志。三条都在**业务侧**，框架侧 11 处日志
  调用全是 warning / error 且不带用户数据 —— 所以本片的顺序是**先堵实证的洞，再给通用机制**。
- **分工的判据照 PRD §4.12**：手机号 / 邮箱 / 身份证 / 银行卡这四种形状换成 code agent 也还是
  这几样，所以规矩放框架；而「哪个字段敏感」只有业务知道，所以名单归业务。
- **两种「脱敏」不是一件事**（本仓已经有一个 ADR-0003）：事件脱敏管**展示层**（工具载荷整条
  不出本进程），日志脱敏管**留痕**（打码之后再写出去）。两件事，两个用，不要合并。

## 代价与边界

- **关掉访问日志是真的少了一层观测**（如实记下）：丢掉的是「每条请求的 URL 与状态码」。
  换来的是**一次性**盖住所有将来被带进 URL 的值 —— 这比给搜索词打补丁强，因为 URL 里还可能
  出现别的东西（会话编号、运行编号）。补观测的地方：启动 / 重试 / 降级那几行自己打，
  外加 `trace` 只读入口（ADR-0018）。
- **框架自己打的异常栈不在本片的覆盖里（已知未堵的一条）**：真机验证时看得一清二楚 ——
  重试提示那一行过了出口、手机号是 `138****0003`，而**同一段供应商正文**在框架
  `charagent.client` 打的「运行异常终止 + traceback」里还是原文。原因是那条日志不经过业务递给
  框架的那个 `writer`，而框架目前**没有统一的日志出口**可以包。它的落点是
  `CharAgent/docs/DESIGN.md` 的 **#38（日志结构化 + 全链路关联）** —— 那一题**还没有切 ticket**
  （注意别与本仓 issue 38「L3b 收口」混了，两套编号）。本片不动它（顺带说明：本片也不动那五个模块
  `charagent.<子包>` 的 logger 命名）。
- **`redact_fields` 这一半还没有生产调用方**：现在的日志全是自由文本（走 `redact_text`），
  结构化日志是 `DESIGN.md` #38 的事。那份字段名单是**给那一刻准备的声明**，今天的价值是「哪些字段敏感」
  在本仓有一处写明的地方（不是配置、不是注释，是能跑用例的代码）。
- **正则兜不住的，这一层就是不遮**（人名、地址正文、订单号在自由文本里原样留着）：那是
  「不打它」而不是「打不掉」——订单号不进日志靠**少记一处**，不靠猜一条规则（猜错了会误伤
  真数据，而误伤的表现是日志里该有的东西没了）。要让某一格**一定**不留原文，声明 `WIPE`。
- **`WIPE` 与字段名写法**：名单里用 `**.字段名` 表示「任何一层出现都算」——同一个字段在不同
  接口里包的层数不一样（账户是平铺的 dict，地址是列表里的每一项），而敏感与否不看层数。

## 考虑过的替代方案

| 方案 | 为什么否掉 |
|------|-----------|
| 搜索词改走请求体（动端点契约） | 要改两侧协议，而 URL 里**还可能**出现别的东西（会话编号、运行编号）—— 治标 |
| 自定义 access log：只打 path 不打 query | 保住了观测，但 path 里的会话编号仍然带买家段，仍要脱敏；代价是要写 asgi 中间件或 uvicorn 的 log config |
| 对上游响应正文按字段脱敏 | 那是**第三方返回的正文**，本层没有它的字段知识（不知道第 137 个字符是订单号还是商品名）—— 正是 #26 说的碰运气 |
| 前端隐藏 / 只在页面上不显示 | devtools 的网络面板里原文可见（ADR-0003 已否过一次） |
| 给订单号也写一条规则 | 订单号的形状是本项目的实现细节，猜错了会误伤 —— 见「代价与边界」 |
| 在框架的重试提示里就地打码 | 那是「出口在哪只有装配处知道」的问题：同一个 `writer` 在服务进程里是日志、在命令行里是终端，框架分不出来（与 ADR-0003 的 `redact=` 必填参数同一条推理） |
| 加一个「演示时关掉脱敏」的开关 | 安全反模式（ADR-0003 已否） |

## 什么时候该重新看这条决定

- **日志结构化（`DESIGN.md` #38）落地时**：`redact_fields` 的名单开始被喂（结构化日志）；**框架异常的脱敏也要在那一片
  一起解决**（现在那条路漏原文，见「代价与边界」第一条）。
- **若要把访问日志开回来**：先得让 URL 里不带用户数据（改契约），否则等于把这个洞重新打开。
- **若业务换了**（不只是换供应商）：名单是业务的知识，跟着业务模块走 —— 框架那四条形状不动。
- **若 `chinesecalendar` 那种「数据会过期」的依赖再出现**（本片的规则没有这种依赖）：
  过期的表现该是「启动期报错」，不是「静默漏打」。
