# 缓存四兄弟的术语是混的 —— 但机制理解基本正确

**证据**（2026-10-10 首课诊断，第 1 题）：用户把「穿透」的定义说成了「击穿」，把「击穿」的成因说成了「雪崩」。

**具体错在哪**：

| 用户说的 | 实际是 | 判定 |
|---------|--------|------|
| 「击穿指查的是空值，永远不命中缓存，打了数据库」 | 这是**穿透**（Penetration） | 术语错位 |
| 「穿透指大量请求短时间内涌来，缓存 TTL 突然到期，海量请求打数据库」 | 这是**雪崩**（Avalanche） | 术语错位 |
| 「击穿的解法是对请求上锁，第一个拿锁的去重建缓存」 | 这确实是击穿的解法**且描述正确** | ✅ 解法对了 |

**为什么这很重要**：用户能描述三者的**症状**，也能说出**解法**（空值缓存、SETNX 锁）—— 缺失的只是「哪个名字对应哪个问题」。这在面试里是**最高性价比的修复**：不需要学新东西，只需要重新贴标签。但它同时是**最危险的**错误类型，因为用户会带着自信说出错误的术语，面试官一听就知道是背串了。

**需要复核的来源**：用户项目里 `app/minimall/todo/redis.md` 与 `cache.py` 的术语是**正确的**（文档里击穿=SETNX 锁、穿透=空值缓存，与实现对得上）。所以错位不是来自项目代码 —— 更可能来自当初学习时的某个二手来源。**下次有机会问一句「你最早是在哪学的这几个词」**，如果是某个具体教程，那份材料要整体打折。

**对后续教学的影响**：缓存这一块的**机制教学可以基本跳过**，直接做「术语矫正 + 升维」。真正欠的是：为什么需要分布式锁而不是普通锁（第 2 题答「不懂」未答）、持久化（第 3 题答错）。缓存线下一课应该从**持久化与内存管理**切入，而不是从击穿/穿透切入。
