# 数据库：应用层手感强，理论词汇表几乎为零

**证据**（2026-10-10 首课诊断，第 4、5 题）：两道数据库题都答「不知道」，并主动说明「特别八股文的知识很少了解，平时直接用的场景比较多」。

**这条记录的价值不在于「不会」，而在于它揭示了缺口的具体形状** —— 用户不是「数据库差」，而是**两套语言不通**：

- **有**：Django ORM 的实战经验、11 个模型的真实建模、MPTT 分类树、`POSTGRES` 用于 CharAgent 快照、alembic 迁移。
- **没有**：四个隔离级别的名字、ACID 中 D 的实现机制（WAL）。

**为什么这个诊断很关键**：面对「理论为零、实践很强」的学习者，**从零讲理论是最糟的教法** —— 会变成用户讨厌的「八股」。正确路径是**先给现象、再给名字**：他一定在真实项目里撞见过不可重复读或幻读（只是不知道这叫这个），也一定依赖过 WAL（只是不知道数据是以什么形式活下来的）。教学要从这些真实经历里把词汇表「长出来」。

**具体教学锚点**（都是用户已有的真实经验）：
- Django 的 `transaction.atomic()` 与 `select_for_update()` —— 讲隔离级别与加锁的入口
- MySQL 默认 RR、PostgreSQL 默认 RC 的**差异** —— 用户两个库都在用，这个差异对他是可感知的
- 用户引以为傲的 `cache.py` 里「缓存与数据库一致性」的取舍 —— 一致性问题的天然素材
- CharAgent 用 PostgreSQL 存快照 —— 正好能讲 WAL 与崩溃恢复

**对后续教学的影响**：数据库线是三条线里**欠账最多**的，优先级应排在缓存之前。第一课就从隔离级别切入（用户明确表示完全不知道），用上面这些真实锚点落地，不用教科书式的例子。

**状态**：已诊断。教学从 `lessons/0001-*` 开始。
