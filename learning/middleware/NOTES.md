## 工作区设备与坑（2026-10-10）

**写入流程**：写完课程 → `python tools/check_lessons.py` → 起临时 `python -m http.server` 用 Playwright 实测 → 停服务。`file://` 被 Playwright 拦，**必须走 HTTP**。

**坑一：`.sim` / `.css` / `.js` 会被浏览器狠狠缓存。** 改完 `assets/` 下的共享文件后，页面上的旧副本会一直被用下去 —— 而且症状很误导（CSS 改了没生效、JS 行为像是没改）。**改共享文件后一律把课程里的 `?v=N` 加一**，然后重新导航。
诊断时的关键手法：在页面里 `fetch(url, {cache:'no-store'})` 看服务端到底送了什么，和 `document.styleSheets[..].cssRules` 看到的对比 —— 两者不一致就说明是缓存，不是代码。

**坑二（更值得记）：两次真实缺陷都是「建好了没接线」，而不是逻辑写错。**
- 第 1 课：测验 JSON 里少一个引号 → 整块数据静默失效
- 第 2 课：`buildLayer()` 把层建好、格子填满，却漏了 `grid.appendChild(box)` → 页面只剩一个空网格，**没有任何报错**

这两个都属于「不抛异常、只是不工作」的类型，肉眼和错误监听都抓不到。**定位手法记下来**：包装 `Node.prototype.appendChild` 打印「挂了什么、挂到哪个元素、那个元素在不在文档里」—— 第 2 课那个 bug 就是靠这招 30 秒锁定的（输出里 `文档里吗: false` 直接指认了孤岛节点）。后续课程遇到「明明建了却不显示」，先上这招。

**面试导向的复习机制**：每课结尾的追问环节要真的做 —— 用户不答就没有证据，learning-records 里就只能记「已讲授」而不是「已掌握」。下次开场先要上一课的答案。

## 调研记录（2026-10-10）

四路并行调研已完成，产出 `RESOURCES.md`。要点与教训：

- **证据分级已建立**：`RESOURCES.md` 里 ✅ = 实测可达，🔍 = 仅见于搜索结果未直接抓取。**继续沿用这个标记，不要偷偷升格**。
- **网络约束**：本机 `WebFetch` 被网络策略整体拦截，可用手段是 `WebSearch` + Firecrawl 抓取。Firecrawl 账户 credits 偏低，大批量抓取前要留意。
- **最有价值的三个发现**（后续课程要反复用）：
  1. **《PostgreSQL 14 Internals》** —— Postgres Professional 出的免费书 + 授权中文翻译，正好卡在「会用 + 懂原理」这条线上，是 PG 部分的主干教材
  2. **Kafka 2011 论文缺副本机制**（原文明写 replication 是 future work），而 ZooKeeper 已在 4.0 被 KRaft 取代 —— 拿它当"现状"讲会被面试官戳穿
  3. **Kafka dev 邮件列表的 KIP 辩论** 是最接近"论文回顾文"的东西 —— 补上了「设计理由」这一类资料的缺口
- **中文资料的版本陷阱**（重要，影响讲课口径）：《Redis 设计与实现》停在 Redis 3.0（无 Streams、无 6.0 I/O 线程）；《MySQL 是怎样运行的》基于 5.7.22；小林coding / JavaGuide 属**二手整理级**，只用来对齐问法、事实必须回官方核实。
- **社区可达性**（国内环境决定实际会用哪些）：V2EX 主域需代理；知乎要登录（+86）；墨天轮是最强的中文数据库从业者社区；CSDN 明确排除，不当社区用；牛客只作面试形式参考、生产智慧为零。
