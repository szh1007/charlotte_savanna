2框架：版本与定位

框架版本（2026-10-10）一句话定位与必考的机制
LangGraph1.2.14 low-level orchestration。必考三件套：① StateGraph + Annotated reducer（状态字段的合并规则， 如 Annotated[list, operator.add] 供并行节点追加）；② checkpointer（短期，thread 级）vs Store（长期，跨 thread） —— 这个区分几乎每场必问；③ interrupt() + Command(resume=…) 做 HITL。 坑：官方明确「最新图定义会立即作用到所有已存在的 thread 状态」—— 改了图代码，跑了一半的旧 thread 会用新逻辑重新解释。

3协议层

3.1 MCP —— 当前规范 2026-07-28（无状态化大改版）

版本序列：2024-11-05 → 2025-03-26 → 2025-06-18 → 2025-11-25 → 2026-07-28（当前）。

核心变化（被问「最新版本有什么变化」时答这五连）：

  1. 无状态化：每个请求用 _meta 携带 protocolVersion / clientCapabilities / clientInfo； 新增 server/discover 取代 initialize 握手；不再有 Mcp-Session-Id。 这才是「MCP 能不能上云、过负载均衡」的答案。
  2. MRTR（Multi Round-Trip Requests）：resultType: "input_required" + inputRequests / inputResponses —— 服务端中途要用户补输入的标准机制。
  3. subscriptions/listen：取代 GET stream 做服务端推送。
  4. JSON-RPC 无 batch；HTTP 头 Mcp-Method / Mcp-Name 支持路由层鉴权；列表结果可缓存（ttlMs / cacheScope）。
  5. 弃用清单（12 个月窗口）：roots / sampling / logging、DCR 动态客户端注册（→ CIMD）、 HTTP+SSE 传输（传输只剩 stdio + Streamable HTTP）。

原语：tools / resources / prompts + elicitation（form / URL 两模式，accept / decline / cancel）。 授权：OAuth 2.1 + RFC 9728 / 8414 / 8707，CIMD 替代 DCR。 治理：2025-12-09 捐给 AAIF（Agentic AI Foundation，Linux Foundation 旗下）。 Extensions（默认关闭、opt-in）：Tasks、MCP Apps（io.modelcontextprotocol/ui）、Skills over MCP。 [规范 · 弃用清单]

3.2 A2A —— v1.0 已发布

  • v1.0.0 发布于 2026-03-12（v1.0.1 为 2026-05-28 patch）；2026-08-27 加入 AAIF。
  • TSC 八家：Google / Microsoft / AWS / Cisco / Salesforce / ServiceNow / SAP / IBM；170+ 合作伙伴。
  • AgentCard 支持 supported_interfaces（JSONRPC / GRPC / HTTP+JSON 三种绑定）；新增 A2A-Version 请求头；spec/a2a.proto 为唯一权威定义。
  • 官方定位一句话（面试直接用）：MCP = vertical（agent 到工具），A2A = horizontal（agent 到 agent），互补不竞争。

4记忆方案

回答框架：先分层，再选方案 —— 比直接说「用向量库存摘要」高一档。

层生命周期代表机制
会话内短期单 thread / sessionLangGraph checkpointer、Agents SDK Sessions、服务端 compaction / context editing
跨会话长期跨 thread，持久化LangGraph Store、Mem0、Zep、Letta memory blocks、Anthropic memory tool
压缩上下文超限时摘要（SummarizationMiddleware）、服务端 compaction

逐个方案（含论文与数字来源）：

  • Mem0 —— ADD-only 单遍提取（不重写旧记忆）+ multi-signal 检索；厂商自报 LoCoMo 92.5 / LongMemEval 94.4； 论文 arXiv 2504.19413；开源 benchmark 集 mem0ai/memory-benchmarks。
  • Zep / Graphiti —— bi-temporal（四时间戳）知识图 + edge invalidation（旧事实失效而非删除）+ 召回链不调 LLM（纯图检索，低延迟）； 论文 arXiv 2501.13956；产品页自报 LoCoMo 94.7%。
  • Letta（原 MemGPT 团队）—— memory blocks（有结构、先审后写）+ MemFS + 「Dreaming」睡眠期整理。
  • LangMem / LangGraph Store —— 官方双路径：hot path（agent 主动调 remember 工具）vs background manager（离线整理）。
  • Anthropic memory tool —— memory_20250818，client-side（工具调用走你自己的存储）， 操作 view / create / str_replace / insert / delete / rename，路径强制 /memories 前缀，支持 multisession。 语义上接近你的 charagent_memories + remember/forget 那一套。
  • 其他：memobase（profile 派，buffer 批处理约 1024 token / 1h 触发）· Cognee（remember/recall/improve/forget 四动词， 单 Postgres 部署）· MIRIX（六分区：core / episodic / semantic / procedural / resource / knowledge vault）。
三个 take-away（可直接讲）+ 一条口径警告
  1. 写入侧趋势：从「LLM 多轮整理」转向单遍 / 批处理（Mem0 单遍、memobase 批处理）—— 成本驱动。
  2. 检索侧最大分歧：召回链里有没有 LLM（Zep 明确不调，省延迟省成本；Mem0 是多信号融合）。
  3. 遗忘与冲突：delete / invalidate / merge 三选一，产品化程度最高的是 Zep 的 edge invalidation。

口径警告（必须主动说）：记忆类 benchmark（LoCoMo / LongMemEval / BEAM）没有统一裁判， 各厂商在自家 pipeline 上自报数字，不可横向比较。主动指出这一点本身就是加分项。

「记忆和 RAG 什么区别」：记忆是「关于用户的、会变的、要遗忘的」，RAG 是「关于知识的、静态的、只增不减」—— 遗忘与冲突管理正是记忆独有、RAG 没有的。

5.2 方法论（区分度最高的簇）

  • 结果评估 vs 轨迹评估：结果（final output 对不对）适合有明确答案的任务；轨迹（tool 调用序列、步数、成本）适合诊断「为什么错」。 分工口径：结果做回归门禁，轨迹做归因。
  • 标准词汇表（Anthropic《Demystifying evals for AI agents》2026-01-09）： task / trial / grader / transcript / harness；pass@k（能力上限）vs pass^k（可靠性）；capability evals vs regression evals。 [anthropic.com]
  • LLM-as-judge 的已知偏差：MT-Bench 论文列 position bias / verbosity bias / self-enhancement bias， 同时给出「GPT-4 judge 与人类偏好一致率 >80%，与人类间一致率同级」的结论 [arXiv 2306.05685]。 缓解：pairwise + 位置轮换 + 长度控制 + 结构化 rubric。实战方法论见 Hamel Husain《Your AI Product Needs Evals》。
  • 工程要点：环境要可复现（container + seed）、工具 mock 与真环境分离、隐藏测试防作弊、每题报成本。

6.2 Prompt caching（机制与折扣）

厂商机制折扣 / 最小长度 / TTL
Anthropic 前缀匹配，顺序 tools → system → messages；显式 breakpoint 写 1.25x(5m) / 2x(1h)；读 0.1x。最小 512 token（不足静默不缓存）。TTL 5m 默认、1h 可选
OpenAI 自动（≥1024 visible token 前缀） 写 1.25x / 读 0.1x（官方口径「up to 95% 折扣」）；TTL 仅 "30m"
Gemini implicit（无保证）+ explicit CachedContent 存储费 $0.50 / 1M token/hour；最小 4,096 / 2,048；默认 1h
DeepSeek 磁盘 KV cache，默认开、无写费 命中价约为未命中 1/50；off-peak 再 5 折

Anthropic 缓存失效的四条件（高频考点）：tool_choice 变化、图片有无、key 顺序、时间戳 —— 任何前缀消息的改动都会击穿。

「agent 场景怎么设计才命中」：系统提示与工具定义放最前且保持稳定 —— 与 Manus 的「mask, don't remove」同源 （工具变更时遮蔽而非删除，保住 cache 前缀）。

6.3 长上下文：「有窗口 ≠ 能利用」

  • Lost in the Middle（arXiv 2307.03172）： 信息位置呈 U 型 —— 放中间最容易被忽略。
  • NoLiMa（arXiv 2502.05167）：去掉字面匹配、要隐含推理时， 11 个模型在 32K 处普遍跌破其短上下文基线的 50%（GPT-4o 99.3% → 69.7%）。
  • 成本维度：有厂商对长输入整体加倍计费（如超过某阈值后 2x 输入 / 1.5x 输出）。

「1M 上下文能替代 RAG 吗」：NoLiMa 证据 + 成本 + 注意力稀释 → 结论 「长上下文改变 RAG 的性价比边界，但不消除它」。

LangChain 的四策略（write / select / compress / isolate）落地件：write = scratchpad / 笔记； select = 检索与规则过滤；compress = 摘要与裁剪；isolate = 子代理与沙箱。

Manus 的六条实战经验（面试很好用）
  1. KV-cache 命中率是 agent 第一指标（成本差异可达 10x）
  2. mask, don't remove —— 工具变更时遮蔽而非删除，保 cache 前缀
  3. file system as context —— 大内容落盘，上下文只放引用
  4. recitation —— 把计划 / 目标反复写入上下文尾部，防跑偏
  5. keep the wrong stuff in —— 把失败留在上下文里，模型才会不重犯
  6. don't get few-shotted —— 上下文里重复的模式会诱导模型机械模仿
