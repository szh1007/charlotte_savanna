4缺口清单（核实版）

建区时的假设，大部分被自己的项目推翻了

建档时按「文件目录里没看到」列了七条缺口，随后逐条核实了 CharAgent/docs/DESIGN.md（70 个难点地图）、 CharAgent/README.md（已实现 vs 已设计未实现对照表）、 CharApp/eval/judges.py。 结论翻转：概念层几乎不缺 —— 缺的是事实层与市场层。 下表是核实后的版本，原假设的推翻记录见 learning-records/0002 与 0003。

4.1 真缺口（本地文件里真的没有）

缺口具体是什么性质
市场情报 外面在问什么、原话怎么说的、哪些题反复出现、非大厂与 AI 公司在问什么。这是信息缺口，不是知识缺口 —— 本地任何文件都不可能回答它，只能向外部检索与面经要。 市场
框架的操作面事实 DESIGN.md #57 已经把判断标准说清了（「能讲清框架替你做了什么、为什么那么设计」是分水岭），缺的是对方的事实： 当前版本下 LangGraph 的 checkpointer / interrupt / store 准确语义、其他框架（LlamaIndex / CrewAI / AutoGen / Agents SDK / Google ADK）的核心抽象。 为什么这对你是刚需：你有自己的挂起-恢复实现，对比题（「和 LangGraph 的 interrupt 有什么不同」）问的就是两者的事实对照 —— 只知道自己那一半答不全。 事实
模型侧机制事实 DESIGN #68 有实测（temperature 被忽略、top_p 下限 0.95、思维链与正文共享 max_tokens 配额、缓存让长前缀近乎免费）， 但缺机制解释：function calling 的协议层细节、structured output 的约束解码、prompt caching 的命中条件、长上下文的真实退化表现。 实测数据是「我知道」的证据，机制是「我懂为什么」的证据 —— 面试问的是后者。 事实
行业共同语言 概念你都有，但叫法可能对不上：轨迹评估 vs 结果评估（trajectory / outcome）、行业基准名（τ-bench / SWE-bench / GAIA / WebArena）、 RAG 评估指标名（faithfulness / context precision / RAGAS）、五个 workflow 模式（prompt chaining / routing / parallelization / orchestrator-workers / evaluator-optimizer）。 面试官用行业词提问时，答不出「哦，我做的就是这个」会被误判为没概念。 市场

这张表改变了课程的重心

如果缺口是概念，课程就该是「讲课」。但核实下来概念几乎不缺，所以主战场是三件事：

  1. 市场对标 —— 拿到外面的真题与措辞，跟你已有的弹药做映射（哪道题你能用 CharAgent 的哪个机制接住）
  2. 压力下检索 —— 知识在代码里、在 70 个难点里，但面试是说出来的。这是技能，要靠自测与追问练
  3. 少量事实补丁 —— 上面 4.1 那四条，量不大但必须有

但注意：「以为知道」和「真答得上」不是一回事。这张表是读码得出的，不是答题得出的 —— 首课的自测就是拿来验证它的（可能又推翻一次）。
