## 起点诊断（2026-10-10 建区时）

用户主动声明的两个岗位方向：**Agent 平台/基础设施** + **LLM 应用/Agent 开发工程师**。时间线 **1 个月内**。自选覆盖域：RAG / 评测与可观测 / 提示工程与上下文工程 / 多智能体与框架选型（四块全选）。

不对称在哪：**项目深度远超面试表达能力**。CharAgent 是零框架依赖的手写运行时（agent loop / 九类事件状态机 / 三实现快照 / HITL / 幂等键 / 上下文压缩 / 脱敏 / MCP 两侧 / 离线评估），素材密度极高；但市场侧（外面在问什么、别人怎么答）是空白。

### 首课自测结果（2026-10-10，用户自报）

| 项 | 结果 |
|---|---|
| 选择题 | 术语题（Harness）、校准题（渐进式披露）**都对**；**判断力题（怎么证明更好）错或犹豫** |
| 口述卡 | **1 / 2 / 4 没答稳**；3（为什么手搓）、5（演示路径）**答稳** |
| 卡点自述 | **「想不起内容」** |

**这个组合的诊断含义（已写进 `learning-records/0005`）**：

- **识别 ≠ 产出** —— 术语选择题答对，但「用 harness 开场」说不出口。这两者是分开的神经通路，必须分开练
- **答稳的两张卡，答案都在他自己的项目里；没答稳的三张，答案都在项目外面**（行业词 / 数字口径 / 术语链）。
  所以「想不起内容」的准确含义是「想不起该调用哪些外部概念来组织回答」
- **推论**：练习必须是产出侧（反查、口述、追问），选择题已经证明能过；判断力题是答题策略问题，不是记忆问题

### 第 2 课自测结果（2026-10-10，用户自报）

失分：第一轮 **d2 Context Anxiety**、**d4 Context quarantine**；第二轮 **r2-2 pass@k**、**r2-4 trajectory vs outcome**。答稳：d1 context rot、d3 context reset、d5 progressive disclosure、r2-1 harness 对位、r2-3 checkpointer vs Store。口径题：**选对但「有一点犹豫」**。

**三个独立信号同时指向评测与口径**：① 首课的判断力题失分 ② 本轮两张评测术语卡失分 ③ 口径题选对但犹豫。而两路调研独立判定「评测是市场区分度最高的一簇」——**他最弱的地方正是市场最看重的地方**。第 3 课因此整课放在评测与口径。

对照实验（本轮给出了一个干净的对照）：**答稳的是「能挂到项目已有做法的词」（context rot↔投影判据、reset↔ADR-0012、progressive disclosure↔DESIGN #51、checkpointer↔快照）；答不上的是「项目里没有对应说法的纯外来词」（anxiety / quarantine / pass@k / trajectory eval）**。→ 记忆钩子的做法被验证有效：把外来词挂到已有东西上（已补进底稿 §2.4）。

> 底稿与课的分工：**底稿给内容（背），课给练习（说）**。用户已选「话术底稿 + 课时」双形态。

> **用户偏好（第 3 课观察）**：他要的是**可以照说的句子**，不是要点。第 3 课的六段「成稿」按口语写，并请他指出不像自己说话的部分（背别人的句式记不牢）。

## 存量素材的真实结构（2026-10-10 盘点）

**结论：纵向深度已经很足，缺的是横向地图。** 五份专题底稿用的是同一套模板：`§0 五分钟版 / §1 行业全景（含一手来源）/ §2 本项目实现（带源码行号）/ §3 面试题演练（高频 · 低频 · 少数了解）/ §4 能讲深的设计 / §5 边界与欠账 / §6 可能被追问的点`，每道题含 `考点 · 知识点 · 类比 · mermaid 图 · 话术 · 我项目里的做法`。

所以**这个教学工作区不重做纵向深挖**，它要产出的三样东西是：

1. **横向地图** —— 外部所有高频主题的清单，标出「哪块已被存量的 5+3 份覆盖」「哪块完全空白」
2. **未覆盖主题的补齐** —— 模型侧基础事实、评测方法论、框架生态细节、提示工程等存量没写的域
3. **压力下的检索练习** —— 存量是「读的」，这里是「说出来的」，靠自测与追问复现

## 两侧调研的收敛信号

中文侧与英文侧**分开检索**，但都指向「评测是最大区分度」（中文侧原话「2026 下半年区分度最高的一簇」；英文侧称 evals 为 *the differentiator*，take-home 里约 20% 是写评估框架），且都把**成本**当必答项。含义：`CharApp/eval` 是被低估的资产。

## 英文侧的结构差异（对备考策略的影响）

- 英文侧**考判断多于考知识**：高频结构是「设计一个 X 并控制成本/延迟/安全」或「这东西坏了怎么查」，而非名词解释
- 英文侧有 take-home 与现场编码：Sierra 的原话是「写一个干净的 agent loop 直接调用模型和工具，**不要用框架**」—— 对你是主场
- 前沿实验室的 values round 常是 gating round（与中文侧「HR 轮随便聊聊」的印象不同）
- 趋势：LeetCode 占比下降（约 70% 高级面试无 LeetCode），项目制/调试式编码与「如何驱动 coding agent」成为正式考点

## 与另一个工作区的关系

`learning/middleware/`（数据库 / 缓存 / MQ）与这里**并列不合并**：知识域不相交，且 middleware 的 MISSION 已写明范围。但两边共享节奏（每周 6 小时）与「被追问」教学法。面试里这两块会**交叉**（例：agent 快照存储选型 → PostgreSQL vs Redis），交叉题的归属在课程设计时按「主要考什么」决定，不必两边都讲。
