# 更正：评测不是「不会做」，是「缺行业坐标系」

建区时把「评测方法论」列为盲区，核实代码后推翻一半。`CharApp/eval/judges.py` 是**纯函数判据集**（不碰网络/库/时钟），并且把口径推导写在了 docstring 里：期望集为空则不进分母（「一个都没调」对纯咨询题是满分）、参数正确率只在真调到的工具上算且与工具选择分池（「名字选错」和「参数传错」是两种修法）、截断/挂起/坏掉的跑次只显示不进汇总（那是跑批器的活，判据不重复 if 终局）。模块 2435 行，五条判据 + 两组 A/B 报告（`44-tools-ab.md` / `45-prompt-ab.md`）。

**Implications**：教评测时**不要**从「什么是 golden set」讲起 —— 那在他既有层之下。要给的坐标是：他的做法在行业分类里的位置（规则判据 vs LLM-as-judge vs trajectory vs outcome），以及规则判据的**能力边界**（开放式生成质量判不了时怎么办）—— 这才是他会被问住的地方。同理适用于其他盲区：**先核实存量，再定缺口。**

**Evidence**：`CharApp/eval/judges.py` 头部 docstring；`CharApp/eval/reports/` 两组 A/B；`wc -l` 显示 7 个模块共 2435 行。
