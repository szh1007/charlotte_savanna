1面试官怎么挖：三层追问结构

2026 年这类岗位的面试结构已经是项目深挖为主、八股为辅。多个一手面经里反复出现同一个动作 —— 面试官围着简历上的每个名词往下追三层[S15][S10]：

层面试官在问什么答不好的后果
第一层
为什么这么设计		 取舍判断。你做这个决定时，另一个选项是什么、代价是什么。 像抄的 —— 说不出别的选项说明没参与决策。
第二层
怎么实现的		 机制。不满足于「我用了 X」，要听到 X 里面发生了什么。 像调包 —— 这是纯应用岗最常见的失分点。
第三层
怎么证明有效		 2026 的分水岭。原话是「优化了多少，怎么测的，有多少人用」[S15]、
「怎么证明新版本真的比旧版本更好」[S2]。		 答不出就从「做过」降级为「试过」 —— 这层的区分度最高。
第三层的坑（来自平台侧的原话）

「简历上写的每个数字都要能讲清楚是怎么算出来的 —— 只报结论不报口径，基本会被一路追到底。」[S10]

对你的具体含义：你有大量真机数字（首字延迟 16.0s → 1.4s、裁剪省 35–38% token、恢复重放两次一分钱没多扣）。 这些是弹药，但每个都要能当场说清「怎么测的、样本几条、和什么比」。

32026 的新词带电区

这一节是首课的最高优先级发现。2026 年冒出一批新说法，而它们描述的东西你几乎全都实现过 —— 你缺的只是那些名字。

行业新词它指的是什么你的对应物
Harness
Agent = Model + Harness		 模型之外的全部工程装置：循环、工具、状态与上下文管理、权限、流式、重试。 提法源自 Mitchell Hashimoto 2026-02-05 的《My AI Adoption Journey》，OpenAI 随后以官方博客背书 [一手：mitchellh.com / openai.com]。 CharAgent 整个就是 harness。被问「解释下 Harness 相关概念」时，你可以拿自己的项目当教科书 —— 这是 2026 的送分题，前提是你会用这个词。
Loop Engineering 把「循环」本身当一个工程对象：循环里在循环什么、怎么防失控、怎么排查。 代表追问是「ReAct 不就是个 while 循环吗，有什么好讲的」[S16]。 九类事件状态机 + 四条硬不变量 + 三种软限制 + kill switch —— 你的循环是这批语料里最规范的一档。
Context Anxiety
/ Context Reset		 两个配套概念：模型在上下文将满时过早收尾、敷衍了事（Context Anxiety）； 压缩不够时干脆重置上下文、把状态外化到外部存储（Context Reset）。 值得记的是 Anthropic 自己留下的一条观察：这个现象在 Sonnet 4.5 上明显，到 Opus 4.5 消失了 —— reset 反而成了负担。工程手段会随模型换代失效。 [一手：Anthropic《Scaling Managed Agents》] 你的「摘要失败不切刀，只有上游报超窗口才允许硬截断」（ADR-0012）就是 Context Reset 的判据化版本 —— 不只是「什么时候重置」，而是「什么条件下才允许重置」。
渐进式披露 Skill / 指令不一次性全塞进上下文，按需分层加载（AGENTS.md 控制在约 100 行是常被引用的经验值）。 DESIGN #51 的「三级渐进披露 + 三级路由」——你已经写过了，缺的是把它叫出这个名字。
为什么这件事排第一

面试里最亏的不是「不会」，是会但没被认出来。你说「我手写了 agent runtime」，面试官听到的是「自己写了个 while 循环」； 你说「harness 层我全部自研，模型接口是最薄的一层」，面试官听到的是「这人在 2026 的坐标系里」。 同一件事，两种评价。

而且这不是我们编的叙事 —— LangChain 官方文档自己的分层口径就是： Deep Agents = batteries-included harness，LangChain = customizable harness， LangGraph = low-level orchestration，LangSmith = trace/debug/evaluate/monitor。 厂商是用「harness」给自己的产品分类的。 [docs.langchain.com]

4自测：把「以为知道」和「答得上」分开

下面 3 道选择题 + 5 张口述卡。选择题立即判分；口述卡要先说出口再展开对照 —— 不出声地「想了一遍」不算数，因为面试考的是检索，不是识别。

术语「Agent = Model + Harness」里的 Harness 指什么？

  • 承载模型推理的服务器、显卡与调度这些底层硬件资源
  • 模型以外的一整套工程装置：循环、工具、状态与上下文管理
  • 统一封装多家模型接口的网关层，负责路由与密钥管理
  • 评测模型能力用的标准化测试装置与一套固定的打分口径
对：模型以外的一切工程装置。 这个等式把「模型能力」和「工程能力」明确切开 —— 而面试官问它，是在探你知不知道自己做的价值在哪一侧。 你几乎 100% 的产出都在 Harness 这一侧：循环、事件总线、快照、HITL、脱敏、工具协议。
出处：Mitchell Hashimoto《My AI Adoption Journey》（2026-02-05）；OpenAI《Harness engineering》。

校准「渐进式披露」在 Skill 体系里解决的核心问题是什么？

  • 让用户逐步看到 Agent 的推理过程，提升产品的可解释性
  • 避免把全部能力描述一次性塞进上下文，按需分层加载
  • 按权限逐级放开工具，防止低权限用户触发高危的操作
  • 让模型先输出摘要再输出细节，减少答案里的冗余内容
对：上下文预算问题，不是可解释性、也不是权限。 这道题是校准项 —— 预期你会答对。DESIGN #51 已经写过「三级渐进披露 + 三级路由」， 如果答错或犹豫，说明这条虽然写过但没进到随口能答的层；如果秒答，说明这块可以跳过。

判断力面试官问「你怎么证明新版本比旧版本更好」，哪种答法最容易被一路追到底？

  • 给出对比结论，并说明两组分别在什么条件下跑的、各几条
  • 先说指标定义，再说这次改动预期影响哪一项指标
  • 给出提升的百分比，并强调这是真实环境跑出来的结果
  • 承认没有量化，转而说明这次改动解决了哪一个具体故障
最危险的是「给数字但不给口径」。 平台侧的原话是：「简历上写的每个数字都要能讲清楚是怎么算出来的 —— 只报结论不报口径，基本会被一路追到底」[S10]。 有口径的结论（选了第 1 项）和主动承认边界（第 4 项）都是安全答法； 唯一会被追打的是第 3 项：数字越大、越强调「真实环境」，面试官越想问「样本多少、跑了几次、和谁比」。

口述 1 · 60 秒：用面试官的语言说清「你的 CharAgent 是什么」

不要用「手写的 agent 框架」开场。想清楚：在 2026 的坐标系里，这东西叫什么？

参考结构（三段）：

  1. 定位：「我做的是 harness 层 —— 从一个 agent runtime 的完整工程装置入手， 模型接口是其中最薄的一层。这样划分的好处是：模型换代时我的工作量接近零。」
  2. 机制：挑三个能证明「不是调包」的：「agent loop 是九类事件的状态机，有四条硬不变量，违反就抛错； finish_reason 六态分流；三种软限制加 kill switch。」
  3. 数字：「1739 个用例、31 条 ADR 记每项取舍的代价与重评条件； 真机上增量渲染把长答复首字 16.0s 压到 1.4s。」

为什么这样开场：一句话把自己放进 2026 的坐标系，后面所有细节都会被自动归位。 反过来，「我手写了一个框架」会让面试官先怀疑轮子质量，你得花更多力气爬回来。

口述 2 · 「你这个系统有多少人用？日活多少？Token 月消耗多少？」

这是业务口径题，个人项目必然没有真实用户量。想清楚：怎么答才不掉分？

参考结构：承认性质 → 给等价的量化替代 → 给成本口径。

  1. 承认性质：「这是我自建的求职作品，没有对外的用户量 —— 我不编这个数。」
  2. 给量化替代：「但我有等价的评测规模：离线评估 20 题 6 场景、两组 A/B，每项跑 3 次取分布； 要验证行为就重跑同一批题。」
  3. 给成本口径：「成本我按真机账算 —— 金额在收尾那一刻按峰谷价算好写死， 逐模型归因；所以我随时能说出某一次 run 花了多少、花在哪个模型上。」

为什么安全：面试官问业务数字的真正意图是「你有没有度量意识」。 「没有用户量但有一套能报出数字的评测装置」比「大概几百人吧」强得多 —— 后者是编的，而面试官一旦发现一个数字是编的，会怀疑所有数字。

口述 3 · 60 秒：「为什么手搓，不直接用 LangChain / LangGraph？」

这题在面经里成对出现：「为什么手搓 agent，而不是用框架」「有没有调研过其他框架」

陷阱：答成「框架不好」会立刻被追问「那你了解它吗」。正确姿势是把「为什么」换成「换到了什么」。

参考结构：

  1. 先承认框架的价值：「框架替你做的是状态与编排的样板 —— LangGraph 用图模型表达控制流、 内置 checkpointer 与 interrupt，省下的主要是编排代码。」
  2. 再说我换到了什么：「我选择手写，换的是控制力：我需要循环语义、事件不变量、 挂起恢复的边界完全可控，而且能对每一处取舍给出代价与重评条件（31 条 ADR）。」
  3. 最后给能力证据：「这条纪律由用例守着 —— 加业务能力不许改 agent/loop.py， 工具超时、熔断、记忆、MCP 四批纯加法都没碰过它。」

加分项：主动说「这条经验反过来也能用 —— 在 charplot 里我就用 LangGraph + DeepAgents 落了一条产品线，知道框架在什么规模下是正收益」。只讲一边会被怀疑二极管。

口述 4 · 「Agent 跑久了上下文腐化怎么办？」

你有一整份底稿可以答这题 —— 这次的要求是：说的时候用上 2026 的词。

参考结构（在底稿之上加一层行业坐标）：

  1. 先给行业路径：「业界的路径一般是三级：先压缩 → 压缩不够再 Context Reset， 把状态外化到外部存储；Anthropic 在长运行 harness 那篇里讲的就是这条。」
  2. 再说我的做法与它的差别：「我做的是账本 / 视图分离：历史 append-only 永不改写， 每次调用前把账本投影成 system + 滚动摘要 + 最近 N 个提问的视图。 关键差别在触发条件 —— 我的设计是摘要失败不切刀，只有上游报超窗口才允许硬裁， 也就是把 Context Reset 变成一条有判据的规则，而不是一个兜底动作。」
  3. 给真机细节：「真机上抓出过两个静态读码看不出的缺陷：投影与切刀合并会让视图隔轮失效、 摘要白烧一半；估算器坐标不一致会高估一倍、低估 20 倍。」

为什么加第一段：不加的话，面试官听到的是一套自创方案；加了之后，你的方案有了坐标 —— 你是三级路径里第二级的强化版。

口述 5 · 面试官说「共享桌面演示一下吧」—— 你的 2 分钟路径是什么？

你的面试形式本来就是演示制，而且有 sh/charapp_demo.sh 一键装置。想过没有：演示什么最值钱？

原则：演示机制，不演示功能。「能买东西」谁都能演示，面试官要看的是只有真做过的人才演得出来的东西。

两个候选（选一个，取决于时间）：

  • HITL 挂起-恢复：触发一次需要确认的写操作 → 看它挂起并落库 → 拒绝一次 / 批准一次 → 看它只补做欠着的那一步、已完成轮次一步不重跑。数字：恢复请求重放两次，一分钱没多扣、工具一次没多跑。
  • 增量渲染：问一道长答复的问题，看首字时间。数字：16.0s → 1.4s。

为什么这两个：前者是「你实现了一个别人只能讲原理的机制」，后者是「你有用户可感知的量化收益」—— 正好落在三层追问的第一层和第三层上。

要提前练的：冷启动 14–30 s 是真的；演示前先跑一遍热身，别让面试官等你 30 秒。 演示剧本和每段兜底动作在 sh/charapp_demo.md。

5被追问三层

现在换我当面试官 —— 你自己先答，答完再找我追问

  1. 针对你的自测结果：哪几道口述卡卡住了？卡在「想不起内容」还是「组织不成话」？ 这两者的修法完全不同 —— 前者要回去翻材料，后者只要练结构。
  2. 针对「稳」的那几档：地图上判定为「稳」的簇（循环 / 上下文 / 记忆 / 工具协议 / RAG / 评测 / 安全）， 有没有哪个其实你答不出来？我判定「稳」的依据是文件里写了，不是你嘴里说得出 —— 这个差集最重要。
  3. 针对「弱」的两档：框架生态与模型侧基础，你想先补哪一块？ 框架那块偏事实（要读当前文档），模型侧偏机制（要理解原理）—— 时间不够时先补哪个，取决于你投的岗位更偏平台还是更偏应用。

直接回复你的答案就行 —— 我会接着追问第二、三层，并按你的实际水平调整下一课。
