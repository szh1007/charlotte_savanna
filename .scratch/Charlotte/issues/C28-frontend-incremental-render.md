## 本票要做的四件事

### 1. `answer_delta` 渲染器：**两档**（Q10-C 的落地）

判据一句话：**最后一个 `\n` 之前算写完，之后算没写完**。

| 帧里有什么 | 怎么画 | 成本 |
|---|---|---|
| **没有换行** | 只往「尾部文本节点」`appendData` | O(1)，零解析 —— 这是绝大多数帧 |
| **有换行** | 把「最后一个 `\n` 之前」解析成块（复用现有 `renderAnswer` 的块规则），尾巴那截（含半截 `**` / 半截围栏 / 刚写的 `- `）**永远当纯文本**挂在新尾巴节点里 | 每换行一次 |

- 未写完的那截**不进块**：与渲染器现在那条「认不出的原样显示」是同一条纪律的延伸
  （半截语法不是「不认识」，是「还没长完」）。
- 每轮（`turn` 变了）换一块新的临时容器：上一轮的尾巴在 `thinking` / `final` 到达时会结清。

### 2. `thinking` 到达时**搬移**（Q13 定案 A）

- 增量先画在答复区（因为它**先到**）；`thinking` 事件一到，说明这一段是**工具轮的正文**，
  不属于最终答复。
- 搬运：取出答复区里「当前轮的临时文本」→ `addStep('思路', text)` → 清掉那块临时节点。
- 结果：**每个字只出现一次**，位置在知道归属的那一刻才定。代价是它会在那一瞬"跳"一下 ——
  与 B 方案（直接丢弃）相比，用户至少不会看到「我刚读过的字没了」。

### 3. `final` 覆盖

- 到达即 `finish()`（清空 + `renderAnswer` 整段），把增量期的一切（尾巴、临时块、过程区里**不**属于
  最终答复的东西）收干净；`[n]` 引用标记**在这之后**才点得开（引用数组只随 `final` 到）。
- 这就是 DESIGN #4 那条「`final` 是权威值、前端收到即覆盖缓冲」的落地 —— 截断拼合场景下增量里可能有
  已作废的内容，覆盖是唯一正确的收尾。

### 4. `reasoning` 渲染器改成**追加**

- `turn.reasoning.set(turn, 旧 + delta)`；思考框**不做 markdown**（纯文本逐字）——
  它是模型的草稿（半截符号、自问自答），给它排版是过度加工，而且它在折叠框里。

### 顺带（一行）

- 改掉 `renderHistory` 上面那条**过时注释**（`:1052-1053`：「同一问之下模型可能说过好几段（中间轮那句
  『我先查一下』也在）」）—— 它只对**没有记录层的内存兜底路径**成立；真实的 DB 路径下 `/history` 按
  `hidden` 过滤（`CharAgent/server/history.py:96-100` 的 docstring 记着这个差别），每个 run 只回一条
  assistant 行。

## 边界与不做

- **不做 markdown 的半截容忍**：半截就是纯文本，等它长完（或 `final`）再进块 —— 这样渲染器那条
  「认不出的原样显示」的安全底一个字不用改。
- **不给思考框做 markdown**（Q16 定案）。
- **不做节流**（帧率真机量过再说）。
- **历史路径一个字不改**：`appendAnswer` 照旧整段渲染（共同定案：历史不重放）。
- **不加 JS 测试基建**：Node 假 DOM 是临时脚本，不进仓库（与上次 markdown 渲染器同一个处置）。

**两个实现决定（票面留白处）**

1. **慢档重画的是「已写完的整段」，不是只画新写完的那几行**。逐行画的话，一个三条的列表会先出
   三个各自独立的 `<ul>`（到 `final` 才并成一个），段落也会被拆开 —— 「逐字」反而更晃眼。
   代价是每次换行 O(已写完字数)，聊天答复这个量级可以忽略。用例把这条钉住了（变异：改回逐行画，红）。
2. **每轮一块 `div.agent-delta`**（票面已定）—— 换轮时上一块**结清**（尾巴也当写完，整段画成块），
   而不是留着半截裸文本。`takeDraftText` 搬运时整块移除。
