# 07 — L2 写 · 退款链路（金额分层 + 角色分离审批）

**What to build:** 退款链路（**阈值与规则在这里，不在框架** —— 见 ADR-0009 的「实现归属」表）。两个工具 + 完整审批链路：

- **`submit_refund(order_no, reason)`**：**金额分层** —— 金额 ≤ 阈值且符合规则（已付款、未超售后期）→ 自动通过并直接创建退款单（走 06 的异步受理，agent 答复「已受理，预计 1-3 工作日原路退回」后 **run 正常结束，不挂起等待**）；超阈值或命中异常规则（如短期内多次退款）→ **工具返回 `Suspension(kind=APPROVAL, ...)`**（ADR-0010 的挂起通道），loop 落帧停下
- **`get_refund_status(refund_id)`**：退款单进度（**从 issue 03 移来** —— 它依赖 06 建的退款单；原计划在 03 造一个「查占位退款单」的工具再回头对齐，时序倒置）

**角色分离**：客服坐席只能**发起**，审批端点是**主管 / 风控**权限，**同一人不得兼顾两侧** —— 框架提供挂起记录里的 initiator 与可注入的审批鉴权钩子（CharAgent P1-7），**角色名单与 SoD 规则在这里**。

**落表**：`charservice_approvals`（审批记录，CharService 自有迁移链）+ 审计（工具粒度 + 数据访问粒度）。

**Blocked by:** 06、**CharAgent P1-15**（`Suspension` 通道）、**CharAgent P1-7**（挂起 / 恢复机制）、**CharAgent P1-4**（幂等）

**Status:** ready-for-agent

- [ ] `submit_refund` 工具可用；金额与售后资格由 minimall service 层判定（工具不复制规则）
- [ ] 小额路径：自动通过 → 创建退款单 → agent 答复受理号与时效 → **run 正常结束**
- [ ] 大额路径：挂起 → `approval_required` 事件 → 审批后从断点恢复（**不重跑已完成动作**）
- [ ] 拒绝路径：失败原因回填模型继续推理
- [ ] 超时路径：15 分钟自动拒绝 → 降级（转人工建议）
- [ ] **角色分离**：客服角色调审批端点 → 403；审批人只能是主管 / 风控
- [ ] 幂等：同 `request_id` 重复提交 → 返回已有退款单，不重复执行
- [ ] 审批台可见挂起项含金额 + 订单上下文 + 该用户历史退款次数
- [ ] 退款全流程经受双粒度审计
