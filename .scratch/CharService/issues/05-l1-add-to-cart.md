# 05 — L1 写：加购

**What to build:** 第一个写操作工具 `add_to_cart(product_id, quantity)`。风险级别 L1（可逆、无资金影响），因此**直接执行 + 回显结果，不走确认卡片**（对比 L2 的 08）。业务侧走 minimall 现有购物车 service（已存在累加与库存截断逻辑），内部端点按委托身份写入对应用户的购物车。**关键约束**：L1 虽不需确认，但**必须有明确的用户意图**——不得在推荐商品时顺手加购，工具描述要写清这条负向指引，让模型知道「推荐 ≠ 加购」。这条约束是「不越权代表用户行动」的最小体现，也是 07/08 引入确认机制前的必要铺垫。

**Blocked by:** 04、**CharAgent P1-4**（幂等键）

**Status:** ready-for-agent

- [ ] `add_to_cart` 工具可用，写入的是**委托身份对应用户**的购物车（身份经 `Injected` 的 `ctx` 取）
- [ ] **挂幂等键**：重放不会把数量加两次（minimall 现有语义是「已存在则累加」，一次重放就是数量翻倍）
- [ ] 工具描述含负向指引：用户仅询问 / 被推荐时不得调用
- [ ] 加购成功后回显商品名 + 数量 + 购物车当前件数
- [ ] 越权用例：用户 A 的 token 无法写入用户 B 的购物车
- [ ] 库存边界：超库存时按现有 service 语义截断并如实回显
- [ ] 变更经受审计（工具粒度 + 数据访问粒度两条都写）
