## 本片要做的四件

### 一、写出 v4（两处改动，一次只改一个变量组）

| # | 改什么 | 为什么 |
|---|---|---|
| 1 | **示例的"回答"行里去掉 markdown 强调**（`**待付款**` → `待付款`，全文件扫一遍同类写法） | 模型会照抄示例的写法。这是 issue 37 真机看到的 |
| 2 | **新增一条禁则：不复述地址与收件人的原文** | 名单 = `phone` / `email` / `receiver_name` / `detail` / `payment_password`（issue 41 那份清单） |

**第 2 条的精确措辞要避开两个陷阱**（都是 2026-09-28 核实出来的）：

- **余额不在名单里**：`get_my_profile` 的工具描述就是"账户+余额"，用户问"我还有多少钱"必须能答。今天有 4 条用例**要求**助手复述余额 —— v4 若禁了它，那 4 条会直接变红，而它们是"用户问了 → 助手答"的正常路径，不是泄漏
- **订单号不在名单里**：所有订单号都不敏感，已有两条用例守着它活着。**v4 里要写清"哪些能说"**（订单号能说），否则模型会走向另一个极端——什么都不敢说

**第三处要动的（写进 v4，但不是禁则）**：说明"地址与姓名这类信息，买家问起时可以确认存在，但不要把原文念一遍"。这条比干巴巴的禁令更能指导模型。

### 二、让跑分器能切 prompt 版本

`MinimallService` 今天**写死**从 manifest 读版本：`prompt_name=f"system/{resolve_prompt_version()}"`（`CharApp/minimall/service.py:397`）。

跑 A/B 要能指定版本，但**不要改 manifest 的 `default`** —— 那个字段的语义是"生产用哪一版"，而跑分是实验。倾向：给 `MinimallService` 加一个可注入的版本（构造参数或装配函数的参数），`None` 时仍走 manifest。

### 三、跑两组

v3 组 vs v4 组，**同一批 20 题 × 3 次**（与 issue 44 共用题集，可比性优先）。

**一处必须先做的手工检查**（否则可能测不出差异）：v4 改的那两样，20 题里**有没有题能触发它们**？

- markdown 强调：模型只在**示例里有那个写法**且回答涉及那个状态时才会照抄 —— 得有一道题会问到"待付款"这类状态
- 复述地址姓名：题意要涉及**收货地址 / 收件人**

不够就补 2–3 条针对性题（加进 issue 42 的 YAML）。**不检查就跑，很可能两组数字一模一样，然后误判成"v4 没用"。**

### 四、报告

用 issue 40 的七块模板，这一组的**主指标是回答合规率**（含 markdown 强调的比例 / 含敏感值原文的比例），工具选择那两个指标是**次要**（v4 不该动它们，若动了要能解释）。

**波动范围照旧要给** —— v4 的改动如果带来的是 +3% 而极差是 8%，那就是噪声。

### 二、v4 改了什么（逐字可 diff）

两处，各自一个变量组：

| # | 改什么 | 落在哪 |
|---|--------|--------|
| 1 | **示例段**里的 markdown 强调全去掉（4 处：`**不要在对话里再问一句"要不要下"**`、`**待付款**`、`**不问密码**`、`**不要问金额**`） | `# 示例` 那一段（v3 的 105 / 108 / 112 / 123 行） |
| 2 | 新增**第 4 条禁则**（账号资料与收货地址的原文不要复读出去，并写明订单号/金额/余额照读）+ `# 回答风格` 里一条说明 | `# 你不能做什么`（后三条顺延成 5/6/7）+ `# 回答风格` |

一处边界是**故意**的，而它也是本片对票面那句"全文件扫一遍同类写法"的**理解**：去掉的
是**示例段**（答复的样板）里的强调，上半篇那 25 行指令（禁则 / 术语 / 回答风格）的强调
**一处没动**（实测 v4 全文 29 行含 `**`、示例段 0 行）。两条理由：

- 票面 §一 那张表的"为什么"一栏写的是**模型会照抄示例的写法** —— 机制落在示例上；
- v4 是**生产候选**（开放决策 1 要看数据决定切不切），把它写成"一句强调都没有"的版本
  会让禁则里那几个重音词一起消失，那是另一个取舍。

**这条理解在复核时有分歧**（见 §八「全文件扫一遍」那条理解分歧）：另一种读法是"全文件那 29 行全去掉"，
那样才彻底隔离"提示词里的强调会不会传染给回答"这个变量。本片按前一种读法落地，
于是 §六 第 2 条的结论**只到"示例那一层"为止** —— 要更宽的结论，得改 v4 再跑两趟
（约 20 分钟），那是下一步的事。

据 `test_v4_only_touches_the_two_places_it_says_it_does`：v4 的示例段逐字等于"v3 去掉
所有 `**`"；上半篇只多出那 7 行、**一行没少**（序号抹平后再比）。

### 三、与票面的出入（四处，都是刻意的）

1. **版本注入口放的是构造参数，不是 `session_for` 的 keyword**。票面倾向"照 `scope=`
   那个形状"，而 `prompt_version` 落成了 `MinimallService` 的字段。理由：版本是**整批
   恒定**的，而装配有**两处**（第一段 + 挂起恢复那一段）—— 放实例上第二段不可能忘带
   （忘带的表现是"一半跑次换了提示词"，而报告上只是一次"两版差不多"）。`scope` 留在
   keyword 上是因为它**逐题**不同，只能由题面算。
2. **"第三处要动的"那句说明落在 `# 回答风格`**，没另起一行示例。票面说"写进 v4，但
   不是禁则"—— 它的内容是"怎么答"，而那一节就是管这个的；示例行是另一个变量组。
3. **markdown 判据写成了第六条默认判据**（开放决策 4 说"要"）。于是它也会出现在 44
   那次实验的报告里 —— 一次 A/B 的两臂必须同一套判据，而"同一套"的定义就在
   `DEFAULT_JUDGES` 那一处，另起一套才是会漂的做法。
4. **没补题**：§三 那处手工检查的结论是"触发能力够"，证据见 §四。20 条仍是 20 条，
   `test_eval_golden.py` 的 `CASE_COUNT` 不用动。

### 四、§三 那处手工检查：不用补题（附证据）

报告里只存答复的**字数**（答复可能含敏感值，不落盘），所以"模型会不会写出 `**`"这件
事在报告里看不出来。于是跑了个临时探针（`Temp/probe45.py`，不进仓库、用完即弃）打真
模型，把答复原文打在终端上，四道题各跑一次（前三道一次扫两处改动，第四道是复核时补的）：

| 题 | v3（清单那一版） | v4 |
|---|---|---|
| `order-03`（下单） | 答复里出现 `**已发货**`；另把收货人姓名念了出来 | 无 `**`；只报订单号与状态 |
| `account-02`（问地址） | 姓名 / 手机号 / 门牌三样原文全念了，还加了 `**默认地址**` | 只说"有 1 个收货地址、是默认那个（浙江省杭州市西湖区那一个）"，指向个人中心 |
| `account-03`（问默认地址） | 同上（三样原文） | 同上 |
| `account-01`（问余额） | 「你账户里还有 9500.00 元。」 | 「你账户里的余额是 9500.00 元.」 |

三条结论：

- **两处改动都真的会发作**：v3 下 3 道里有 2 道写出 `**`，2 道泄漏原文 —— 不是"跑了
  一趟没测到"。另有 issue 44 报告的底数佐证（v3 下 `account-02` / `account-03` 各
  6/6 跑次泄漏）。
- **题集够用，不必补题**：地址那条的触发面是 4 道（`account-02` / `account-03` /
  `order-02` / `order-03`），markdown 那条是"任何报状态的题"（实测 `order-02` /
  `order-03` / `product-03` 都中过）。
- **v4 没有走向"什么都不敢说"**：`account-01` 那一跑直接把余额答了出来（两版都答了）
  —— 这是"那条禁则没管到余额"的直接证据。报告里的 `answer_chars`（17–23 字）只是间接
  迹象，本条以探针那次逐字看到的为准。
- 探针的**终端输出**里当然有答复原文（那是看到泄漏的唯一办法），本页只写"念了哪几样"、
  **不抄原文** —— 与那条 markdown 判据不引答复同一个纪律：一段引文就把"泄漏了什么"
  抄进了一份长期留存的文件。

> 探针顺手撞出一处**装置缺陷**（不归本片改）：假商城 `POST orders/` 回的是
> `ORDER_DETAIL`（已发货 / 1899.00），而下单真机上回的是一张**待付款**的单 ——

> 留给 46 决定要不要修（改了要重跑两个 A/B）。

### 六、结论

1. **改动 2（不复述原文）成立**：两趟都是 100%（违规 0 跑、臂内极差 0），对照组每趟
   8–9 跑违规，题面全压在 `account-02` / `account-03`（各 3/3 全中）与 `order-02` /
   `order-03`（订单详情与下单的回执里带着地址快照）。**差额 13.6 / 15.0 个百分点，是
   v3 侧臂内极差的 2.3 / 1.5 倍**，两趟同向。

   **"干净"的边界要说清**：干净的是**判据要搜的那五样**（手机号 / 邮箱 / 收件人姓名 /
   门牌 / 支付密码 —— 最后一样由 v3 就有的第 1 条禁则管着，且它从不进 wire）。v4 照旧
   说得出"浙江省杭州市西湖区"这类**不在名单里**的信息（探针里逐字见到）—— 那是判据与
   提示词**同口径**的结果，不是漏网：v4 的措辞把禁的范围写成"手机号 / 邮箱 / 门牌号 /
   收件人姓名"，省市县不在其列。要不要连"哪个区"一起收进去，是 46 该定的边界（改了
   要重跑）。
2. **改动 1（示例去强调）不成立** —— 但把它**断在哪一层**要说准：

   - **测到的那一层**：两趟两臂都在 88–92%，差 ≤2 个百分点，落在极差内；违规的题两臂
     高度重合（`order-02` / `order-03` 两趟两臂都中）。也就是说**把示例写干净，并没有
     让模型少写 `**`** —— 那条改动原本针对的机制（"模型照抄示例的写法"）在这一层上
     是无效的。
   - **没测到的那一层**：上半篇那 25 行指令里的强调还在（§二 那条边界），所以由这份
     数据**不能**推出"提示词里的强调与回答里的 `**` 无关"。要那个结论，得把全文件的
     强调一起去掉再跑（复核时提的，见 §八「全文件扫一遍」那条理解分歧）。
   - **下一步的方向**：想让页面上真的不见星号，从这份数据看，**明文禁止**比"把样板写
     干净"更像那条路 —— `policy-02`（一个工具都不调的咨询题）两趟也中过，说明模型是
     在自己写、不是在抄某一句话。那是**第三个变量组**，属于新写一版（v5 那一路）。
3. **钱**：v4 两趟都贵一点（+10.8% / +10.5%），token +5.6% / +7.5%，轮数几乎不变。
   方向一致、量级不大 —— 正文只长了 636 字节，差价主要来自答复更长（新禁则让它多
   解释一句"可以确认存在、要完整信息去个人中心"）。
4. **工具选择**：两趟都是 v4 略低（3.1 / 2.0 个百分点），但两趟都**小于本臂极差** ——
   按 44 立下的规矩（"差小于极差就是噪声"）不能算。与 44 的结论一致（那次也是噪声）。
5. **一处装置缺陷**：见 §四 末尾那条引用块（假商城 `POST orders/` 的样本与真机不符）。

### 八、两轴复核（Standards / Spec）的处置

两轴各起一个子代理跑的（Standards：对照本仓的注释/命名/风格纪律 + 一组通用的坏味道
清单；Spec：对着本票逐条核，并复核本页实施记录的说法）。**硬违规 0 条**，下面是
judgement call 的处置。

**改了的（5 处）**

1. **开跑前不验版本这件事被指出来了**（Standards 轴："版本是裸 str 走四层，校验只在最
   底层"）。复核说得对：跑批器那条开跑前自检验的是"对象装得出来吗"，而版本是**跑到
   第一题**才读的 —— 一个写错的版本号会让 120 跑一起记成 `BROKEN`，入口那句"报告落盘"
   照样报成功。处置：**没有引入新类型**，而是加了 `check_versions(arms)`（`build_groups`
   里调，`MinimallConfigError` → 入口那句"启动失败"），并用例断"造模型那一步一次都没被
   调到"。不造新类型的理由：版本号是**字符串**这件事贯穿服务 / 清单文件名 / 报告那一格
   三处，包一个类型只是把这四处挪成"类型 ↔ 字符串"的来回换。
2. 测试里硬编码的 `"system/v4"` → 改成 `f"{PROMPT_NAME}/v4"`（与同批另一条用例一致）。
3. `judges.py` 里那个 `found` → `has_mark`（同页 `ComplianceJudge` 的 `found` 是个列表，
   同名不同物）。
4. `test_prompt.py` 的模块 docstring 说"下面三件事可以"，而这一页已经五件事了 → 改成
   五件并补上第 4 / 5 条的说明。
5. `test_prompt.py` 的 `_NUMBERED` 常量原先夹在一个用例与它的 helper 之间 → 挪到顶部
   常量区（与 `CURRENT_VERSION` 放一起）。

**没改、记下理由的（4 处）**

1. **票面那句"全文件扫一遍同类写法"被读成"整个文件那 29 行 `**` 全去掉"**（Spec 轴）——
   本片没改实现，按"示例段"那一层落地（理由见 §二 那条边界）。分歧的实质是**变量隔离
   到什么程度**：全去掉才彻底，只去示例才保住指令里的重音。**这条留给你定**：要更宽的
   结论就改 v4 再跑两趟（约 20 分钟、约 ¥0.2），数据与说法会被 §五/§六 一起换掉。
   §六 第 2 条的结论已按"只到示例那一层"改写。
2. `Arm` 一个类型带两个开关、`name` 在两次实验里含义不同（Data Clumps / 双模式）——
   保持。"一次实验只拨一个"由 `test_each_experiment_flips_exactly_one_switch` 在表那
   一层钉着；拆成两个类型会让 `EXPERIMENTS` / `build_groups` 那套机械翻倍，而它服务的
   只有两次实验。
3. `MARKDOWN_MARK` 在 `judges.py` 之外没有消费者（Speculative Generality，弱）——保持。
   它是那条**规则的定义**，与同页的 `PARAMS` / `RECALL` 同级；门面镜像各子模块的
   `__all__` 是本包的既有做法。
4. v4 新禁则没点名**支付密码**，而票面那句"名单"里有它 —— 保持。那条禁则管的是"买家

   密码"），而且它从不进 wire（ADR-0015）—— 模型没见过的东西复述不出来。判据照样搜
