## 一、20 道题的形状与分布

**题是数据，不是代码** —— 放业务侧 YAML（与 `prompt/manifest.yaml` 同一种风格），加一条题 = 加一段 YAML，badcase 回流才有低成本可言。

```yaml
- id: product-01
  scene: product                    # 六个场景之一
  question: "有什么 2000 块以下的手机推荐吗"
  expect_tools: [search_products]   # 期望工具集（可为空 = 期望不调工具）
  expect_params:                    # 可选：命中的工具里，这些参数要对
    search_products: {max_price: 2000}
  expect_suspend: false             # 是否期望走到挂起
```

**六类场景各 3–4 条，共 20 条**：

| 场景 | 条数（倾向） | 覆盖什么 | 备注 |
|---|---|---|---|
| `product` | 3 | 搜索 / 详情 / 分类 | |
| `cart` | 3 | 查看 / 加购 / 改量移除 | 含一条"清空" |
| `order` | 4 | 列表 / 详情 / **下单** / 取消 | 下单那条 `expect_suspend: true` |
| `refund` | 3 | 申请 / 查进度 / 说退款别换取消 | 第三条踩的是 v3 里那段术语区分 |
| `account` | 3 | 余额 / 地址 | **余额那条判据要放行余额复述**（见下） |
| `policy` | 4 | **期望零调用**的咨询类 | 见下面那个坑 |

**`policy` 那四条是本片最容易写错的地方**：它们的 `expect_tools` 是空的（"你们几点发货"这类），于是：

- 召回率无定义（分母是 0）
- 准确率也大概率无定义（分子分母都 0）

**处置：两组指标各自单列不适用样本**（L4 规划期已定）。报告里要有一行"零期望样本 4 条 / 零调用样本 N 条"，让读者知道那两个比例是在多少样本上算的。

**题面不能出现敏感值原文** —— 若题面写"我的地址是文三路 100 号"，模型复述它就是**正常的**，回答合规判据会误判成违规。题面用"我的收货地址"这类说法。

## 二、判据：三个指标 + 回答合规 + 三分类

### 三个指标（口径已定死，2026-09-28）

| 指标 | 算式 | 边界 |
|---|---|---|
| **召回率** | `|实际 ∩ 期望| / |期望|` | `|期望| = 0` 时**不适用**（单列） |
| **准确率** | `|实际 ∩ 期望| / |实际|` | `|实际| = 0` 时**不适用**（单列）。理由：有些题的正确答案**就是**不调工具直接答，把正确的零调用算成 0 会惩罚正确行为 |
| **参数正确率** | 命中的工具里，`expect_params` 点名的键有几个对上了 | 单列，**不混进上面两个** —— 名字选对了但参数传错，是"选对了工具、用错了参数"，混一起出问题时分不清该改 prompt 还是改工具描述 |

**三处去重/计数约定**：

- 两边都按**集合**算（同一个工具调多次算一次）。否则模型的重试行为会污染指标，且污染方向还不一致
- 分子分母按**全部样本合计**（不是 3 个比例取平均）
- 报告另附**3 次各自的数** —— 那三个数的极差就是波动范围，它决定了「这次改得比上次好」这话能不能说（见 issue 44 的验收）

### 回答合规（v4 要用）

拿 issue 41 的敏感值清单去**最终回答文本**里搜，搜到即违规。清单 = `phone` / `email` / `receiver_name` / `detail` / `payment_password`，**不含余额**（余额是助手被设计来做的事，现有 4 条用例要求复述它）。

**订单号不在清单里** —— 所有订单号都不敏感，且已有两条用例守着它活着。

### 三分类结局（硬要求）

> **issue 40 落地时改成了四类**（多一个 `BROKEN`：上游打断 / 跑批抛错 —— 它既不该算进「截断」也不该算成「答错」，否则上游抖动会污染截断那个数字）。分类**用 `CharAgent.eval.run_outcome_of(result.outcome)`**，别自己 if。下面这张表的三类语义一字未变。

| 结局 | 判据 | 怎么算分 |
|---|---|---|
| `passed` | 正常答完 | 进指标计算 |
| `truncated` | 被 token 预算截断（`token_budget` error） | **不进准确率/召回率**，单列计数 |
| `suspended` | 停在挂起（未决） | 单列（issue 43 会把它变成"已确认"，那时按 `passed` 算） |

**为什么不能让截断算"答错"**：全挂组的 prompt 前缀更长、更容易撞上 60k 预算 —— 把截断算作失败会**压低全挂组**，让裁剪组显得更准，而那个差异来自"前缀短"不是"选得准"。判据与报告都按三分类写，别把这条丢掉。

### 给 issue 43 / 44 / 45 的话

- **超限那一题要换买家**：读 `case.meta["buyer_id"]` 传给 `harness.context(..., user_id=)`；默认值就是样本那个买家，题集里只有 `order-04` 指了 `BIG_CART_BUYER`。不换人的话那一题会挂起（2598 < 5000），而挂起不进汇总。
- **挂起那一题只有 `expect_suspend: true`**（`order-03`）：它是给 43 的恢复流程看的，**不是判据** —— 护栏判据只读 `meta.expect_refusal`。43 让那一跑走完确认之后，终局会是「跑完」，而 `expect_suspend` 照旧留着（它说的是「这一题会走到那个点上」）。
- **45 那条 markdown 禁则**：加进 `ComplianceJudge`（或新开一个判据挂进 `DEFAULT_JUDGES`）都行；比例要池化就在 `Judgment.metrics` 里加一条（`Metric(hit, total)`），别在 `ok` 上想办法。指标名拿 `judges.RECALL / PRECISION / PARAMS` 那几个常量对齐。
- **加题 = 加一段 YAML**：但 `test_eval_golden.py` 里的 `CASE_COUNT = 20` 与场景分布是写死的（两个 A/B 共用同一批题，题数变了该被人看见）。题号写成 `<场景>-<两位序号>`，校验会替你看着工具名与场景名。
