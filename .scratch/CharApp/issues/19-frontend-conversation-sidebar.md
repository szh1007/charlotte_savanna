## 做什么

把客服页做成 DeepSeek 网页版那种形状：**左边一栏会话列表，能新建、能切回；右边是当前这段对话**。加**压缩发生时的那一行灰字**（让「框架在替我省钱」这件事看得见）。

会话编号**不进 URL**（ADR-0002 与 issue 13 复核时定下的纪律），所以侧栏的选中态只能走请求体与本地状态，不能做成 `/minimall/agent/?c=…`。

## 具体任务

### 1. 布局

- 左栏约 **260px 固定宽**，主区是现有对话区；页头保留（不要动 `base.html` 的导航）
- 左栏在窄屏 / 移动端**不折叠**（演示用桌面，写进注释免得以后被当漏项）

### 2. 列表

- 数据来自 `POST /minimall/agent/conversations/`（issue 18 铺好的通路），**页面加载时拉一次**
- 每项：**标题**（首条用户消息截 ~20 字）+ **相对时间**（刚刚 / N 分钟前 / N 小时前 / 日期）+ **当前会话高亮**
- 排序由后端给（`updated_at` 倒序），前端不重排
- **一个会话都没有**时显示一句空态文案（比如「还没有历史对话」）
- **没聊过的会话不显示**（懒创建的必然结果，后端已经过滤，前端别自作聪明补一行）

### 3. 「新对话」

- 按钮在左栏顶部。点击 → 换一个新的会话编号（沿用 `newConversationId()`）+ 清空主区 + 列表高亮取消
- **不落库**：会话行是「第一条消息发出去」时才由记录器创建的（issue 17 的懒创建），所以点了新对话又不用，列表里不会多出一条垃圾

### 4. 切换

- 点列表项 → 切到那段：更新当前会话编号、清空主区、拉该段历史并重绘、高亮跟着走
- **正在流式回答时禁止切换**（列表项置灰 / 点击无效）—— 否则半截事件会落进另一段对话里。回答结束（终局事件）后恢复
- 切换失败（历史拉不回来）要**安静降级成空历史**而不是弹错 —— 服务端历史可能因为任何原因缺失，但列表项还在

### 5. 刷新语义（**一条已经拍过的取舍**）

- **刷新 → 回到本标签页刚才那段**，保留 `sessionStorage`（issue 13 验收过「刷新对话还在」，不能推翻）
- 用户原话是「每次进入客服页就创建新会话框」—— 落地成：**进页面时若本标签页没有当前会话，就是一个空的新对话**；「随时开一段干净的」这个需求由「新对话」按钮满足
- 换标签页 → 各是各的（沿用现状）

### 6. 压缩那一行灰字

- 后端新增的第七类事件（issue 16）到前端时渲染成**一行不显眼的灰字**（比如「已压缩更早的 12 条消息，估算省下约 3.2k token」），挂在这一轮里、与工具行区分开（工具行说的是"做了什么"，这一行说的是"上下文治理"）
- `RENDERERS` 表加一个键；**别忘记** `test_bff.py:1086` 那条「六种事件都有 handler」的用例要跟着改成七种

### 一、定案（票里没写死、实现时才定的）

| 决定 | 理由 |
|------|------|
| 左栏 260px 固定宽，`.agent-page` 从 880 放宽到 1180 | 与 `.container` 的 1280 上限留出边距；主区 `flex: 1; min-width: 0` |
| 压缩那行用**独立版式**（`.agent-compact` 小灰条），不是工具行那套「标签 + 正文」 | 票要求"与工具行区分得开"：工具行讲"做了什么"，这一行讲"上下文治理" |
| 标题截 20 字（库里最长 60，`recorder.TITLE_LIMIT`） | 列表一行放得下 |
| 相对时间超过一天就报**日期**（同年不带年份） | 「几小时前」跨天之后不再有用 |
| 「新对话」也一起锁（答到一半按不动） | 它同样是一次换会话；不锁的话半截事件会落进那段新对话里 |
| 列表的失败路径**静默留白** | 与读历史同一条：首屏辅助件失败不该打扰用户。那时说「还没有历史对话」是**撒谎**（可能有，只是没拉回来） |

### 二、与票有一处**有意的不一致**：相邻的同文灰字只画一条

票 §6 说「渲染成一行不显眼的灰字」，验收说「压缩发生时主区出现一行灰字」。
而框架的 `context_compacted` 是**按轮**报的 —— 真机的帧序是：

```
context_compacted → reasoning → tool_call → tool_result → context_compacted → final
```

一次问答里模型决策两轮，两轮都切了一刀，于是**两条事件**。摘要降级时（issue 18
的开放项 1：真机上摘要那一半一直降级）两轮的 `dropped` / `truncated` / `saved_tokens`
**一模一样**，只有 `summarized` 不同 —— 拼出来是同一句中文。

第一版按「与 `steps` 的最后一个孩子比」去重，真机上**没生效**：两轮之间刚好插了
一条工具行，最后一个孩子是工具行不是灰字。那一跑在页面上连出 **5 条一模一样的
灰字**（阈值被我压到 800，每轮都切）。改成「与上一条**灰字**比」之后，同一跑只剩
1 条。

**这是一处有意的偏离**：同一个动作在同一轮里连出两条同样的话，看着像坏了（而这是
本片最要紧的演示资产）。少画的那一条**没有丢信息** —— 它与前一条逐字相同。计数
不同时两条都会画。

### 三、票外多做的两件（各自理由）

1. **一轮答完顺手重拉一次左栏**（`end()` 里那次 `loadConversations()`）。票写的是
   「页面加载时拉一次」，但会话行是「第一条消息发出去」时才建的（懒创建）—— 只拉
   首屏的话，**这一页刚聊出来的新会话要等下次打开页面才出现在左栏**，左栏就成了
   摆设。代价是每轮多一次库读。
2. **`relativeTime` 跨年补年份**。列表里绝大多数是最近的，多一个年份只是噪音；
   但跨年那条不补就分不清是哪一年的。
