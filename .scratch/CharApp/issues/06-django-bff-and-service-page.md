# 06 · Django BFF + 客服页面

**Status:** ready-for-agent

**Type:** task

**Blocked by:** 05

**上游:** `../PRD.md` §4.2 / §4.10 / §4.11 / §4.9（L1b）、`CharApp/docs/PLAN.md` §4

## 做什么

**L1b 的主验收切片**：浏览器打开 minimall 的客服页，用已有登录状态问一句「我最近的订单到哪了」，看到流式回答 —— 内容是真实订单。多买家各自登录、各自看到自己的数据。

这一片把最后一层（Django BFF + 前端）接上，链路才算走完。

## 具体任务

### 1. Django BFF 端点

`/api/minimall/agent/` 这个前缀已经属于「token 认证的内部端点」（issue 02），BFF 是**session 认证的用户面端点**，两回事 —— 换个前缀，别混在一起。

职责只有三件，多一件都不做：

1. **认证**：登录用户才能用；未登录跳登录页，不是 500、也不是空流
2. **取身份**：`user_id` **只从 session 取，绝不看请求参数**（见下方第 6 条）
3. **转发 + 透传**：带内部令牌 + `X-User-Id` 打 CharApp 服务，SSE 逐块透传给浏览器

BFF **不做业务判断** —— 不判断「这句话该不该问」、不改写问题、不缓存回答。

### 2. SSE 逐块透传的实现选择

Django 的 `manage.py runserver` 是同步 WSGI + 多线程。转发侧的合理选择是**同步 httpx 流式读 + `StreamingHttpResponse`**，不要为了「异步」把 BFF 复杂化。

（真要上 ASGI 是部署期的事，与 L1b 的目标无关。）

### 3. 客服页面

- **原生 JS + `EventSource`**（PRD / PLAN 定的），与商城前端零构建、htmx + Alpine 的既有风格一致 —— 不引入构建链、不引入 UI 库
- 入口放**导航栏**，全站可达 —— 用户故事 23「一边看商品页一边问」要求它不只在某一页存在
- 事件渲染：`thinking` / `tool_call` / `tool_result` / `reasoning`（折叠，它是心理活动不是答复正文）/ `final` / `error`

### 4. `EventSource` 的重连陷阱

`EventSource` 在流结束后会**自动重连** —— 对同一个 GET 再发一次，等于把用户那句话重复跑一遍。必须收口：

- 终局事件到达后客户端主动 `close()`
- 必要时让 BFF 在终局后关闭响应，让重连无从发生

这条不处理的话，表现是「每次问完，账单上多一份」而不报错。

### 5. 会话标识的第三段

`thread_id = minimall:{user_id}:{conversation_id}`（PRD §4.11）。

- `conversation_id` 由前端**每个标签页**生成 —— 用户故事 25「两台设备各聊各的」靠它成立
- 框架对 `thread_id` 有校验：非空、≤128 字符、不含空白与控制字符（`checkpoint/utils/types.py:54-88`）。把生成规则设计成天然满足，不要靠传进去才报错

### 6. 跨进程错误传播

L1b 相比 L1a 多出来的五个新变量之一，也是最容易漏的一个。三种故障要各自有明确的用户可见表现：

| 故障 | 浏览器上看到什么 |
|------|-----------------|
| CharApp 服务没起来 | 一句人话，不是白屏 |
| 商城没起来 | 助手说「暂时查不到」，不是伪造数据 |
| 模型报错 / 额度用尽 | 明确的错误提示，不是转圈到超时 |

**归因分界**：框架只给事实（错误码 + message），**用户面文案归业务侧**（框架的 `docs/DESIGN.md:113` 明文写着「降级话术归 server 层，框架不编造用户文案」）。所以文案写在哪一层要有说法。

### 7. 多买家与多标签页隔离（本片的验收主体）

机制在 L1a 就免费得到了 —— 快照按 `thread_id` 分区，而 `thread_id` 里已经含 `user_id`。本片要做的是**证明它真的没漏**，而不是重新设计它。

- 两个买家各自登录 → 各看各的（用户故事 24）
- 同一买家两个标签页 → 各聊各的（用户故事 25）
- **守卫测试**：请求里塞一个别人的 `user_id` 参数 → 仍然返回自己的数据。这条对应 PRD §5 那句「不能靠『我记得』」

### 8. 写测试

商城侧用 Django 测试客户端；跨进程那段用假 CharApp 服务（或直接把 05 的服务挂在 ASGI transport 上）。

## 备注

- **`EventSource` 只能发 GET、不能带自定义头** —— 认证靠 cookie（这正好就是「用已有登录状态」的实现方式），对话内容走 query 参数
- 页面上的对话历史：L1b **不做**历史消息接口（框架侧的会话历史是给模型看的，不是给前端渲染的）。刷新页面就是一段新对话 —— 这是本片的已知边界，写进备注而不是假装它不存在
- 别在 BFF 里加 `print` 调试 —— 项目用标准 logging（系统级规范 §6.3）
- 前端的样式跟随商城现有风格（`templates/minimall/base.html` 的色板与圆角），别引入新的设计语言
