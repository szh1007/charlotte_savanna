## 做什么

用户在真机上摸过客服页面之后提的四条反馈（2026-09-23），加一条**由第 3 条牵出来的框架行为收窄**：

| # | 用户原话（要点） | 本片要做的 |
|---|-----------------|-----------|
| 1 | 置顶后看不出来是置顶的 | 列表项加置顶标识（📌 + 主色加粗） |
| 2 | 改名只有回车才生效，点别处不提交 | 失焦即提交（与回车同一条出口） |
| 3 | 搜「你」两个会话都出来；要按按钮/回车才搜 | 触发改显式；**范围收窄到只搜标题** |
| 4 | 点进会话先蹦横幅、再蹦历史 | 加加载态；顺带补失败态（现在完全静默） |

这四件**全是手感修正，不是新功能**。只有第 3 条的「范围」那一半要动框架、删一条**有名字的测试**，并为它配一条 ADR —— 代价写在下面。

## 具体任务

### 1. 前端 · 置顶视觉（`agent.html`）

- `Boolean(row.pinned_at)` 现在只在 `actionMenu` 里算（`:745`），把它**提到一处**、列表项与菜单共用 —— 两处各算一遍的话，哪天判据变了只会改到一处。
- 置顶项：标题前加 📌 + 标题用主色 `#ff6b6b` + 加粗。

- **排序一个字不动**（后端已排好）—— 这条也写进注释，免得以后被当漏项。

### 2. 前端 · 改名失焦即提交（`agent.html`）

- `blur` 的出口从 `cancelRename` 改成 `submitRename` —— **`Enter` 与 `blur` 从此同一条出口**。
- 两道原有守卫**必须留着**：`input.dataset.busy`（提交在飞，别重入）与 `!input.isConnected`（`Escape` 已经把它换掉了，这次失焦不算）。**少了后者，`Escape` 会紧跟一次提交** —— 验收里有一条专门钉它。
- **失败行为要改**：现在是「把 input 留在原地 + 抢回焦点」。失焦触发时抢焦点会**打断用户刚点的那一下**，所以失败统一改成 **回滚成原名 + 列表上一句提示**。
  - 代价写明：用户的输入丢了，得重打一遍。换来的是一条行为，不是两条。
- 「禁止清空」= **现状**（`submitRename` 里 `!title` 走 `cancelRename`），不用加代码，但验收要钉。
- **三条注释一起改**（`:849-853`、`:781-783`、`:1053-1054`）：它们现在都写着「点别处 = 放弃」。

### 3. 前端 · 搜索改成显式触发（`agent.html`）

- 加一颗搜索按钮；`Enter` 也触发 —— 搜索框**不在 form 里**，得自己绑 `keydown`。
- 去掉 `SEARCH_DEBOUNCE_MS` 那条防抖路径；**「清空输入框立刻恢复全部」保留**（用户明确要的）：`input` 事件只在「框变空且上一次非空」时直接重拉。
- `searchTerm` 的语义跟着变：它要表示**已提交的那个词**（不是输入框里的实时值），因为 `renderList` 用它决定空列表说的是「没搜到相关的对话」还是「还没有历史对话」（`:930-935`）。
- `:999-1001` 那段「输入即搜」的注释一起改。

### 4. 前端 · 加载态与失败态（`agent.html`）

聊天区的四种状态要**互斥且分得清**：

| 状态 | 什么时候 | 画面 |
|------|---------|------|
| 加载中 | 在等一段**可能已经有内容**的历史 | 居中转圈 |
| 空 | 加载完 + 这段会话没有可见消息 | 引导横幅 |
| 有历史 | 加载完 + 有消息 | 历史 |
| 失败 | 网络 / 非 200 / 非 JSON | 一行「历史没加载出来 · 重试」 |

- **转圈与横幅的取舍只看一件事：这一次加载是不是在等一段可能已经有内容的历史。**

  | 触发 | 会等什么 | 横幅 | 转圈 |
  |------|---------|------|------|
  | 点列表里某一条 | 一定有（列表只列有可见消息的会话） | 摘掉 | 要 |
  | 首屏，且 sessionStorage 里有编号 | 可能有 | 摘掉 | 要 |
  | 首屏，且编号是新生成的 | **一定有**（uuid 独一份，库里不可能有） | 留着 | 不要 |
  | 点「+ 新对话」 | 同上 | 留着 | 不要 |

  这条规则**比"两处都加 spinner"更准**：给一段刚生成的编号转圈是在演一个假动作。它落在 `loadConversationId()` 已有的两个分支上（存过 / 没存过），**不新增状态**。
- 由此 `clearChat()` 要**改形状**：它现在无条件 `appendChild(hint)`，这正是 #4 的根因。改成只清空，由上面那张表决定放什么。
- `startTurn()` 要**顺手清掉转圈与失败行**：用户可以在转圈期间直接提问（`loadHistory` 那两道 `!finished` 守卫正是放行这条），不清的话那一圈会永远转下去。
- 失败行那颗「重试」重跑 `loadHistory`，**先把自己摘掉**再跑。
- 转圈**只放聊天区**，左栏不动：左栏是它自己的一次拉取，两个 spinner 同时转更乱。
  - **2026-09-23 收尾后用户追加**：左栏**搜索**那一条也要转圈（他按了搜索，人正盯着列表等结果）。改法是给 `loadConversations` 加一个 `searching` 选项，只有**搜索那一行**发起的请求才摆 —— 别的时候列表是在**原地**重拉（每轮答完 / 三个管理动作之后），每拉一次都摆一下就是闪，而用户并没有在看列表。**这条推翻了上面那半句**：代码与验收都以追加的这条为准。

## 备注

**两处与上一轮问答有意不一致**（都是核代码之后改的，不是漏做）：

## 实际开发情况

### 一、定案（票里没写死、实现时定的）

- **搜索那一行做成一个 `<form>`**：回车提交由它白送，不必自己绑 `keydown`（任务 3 原本预计要手绑）。按钮 `type="submit"`，两条触发走同一个出口。
- **四态收成三个构造函数 + 一个 `setChatPlaceholder(node)`**：横幅 / 转圈 / 失败行在同一时刻只留一个。那个 `hint` 节点**从不销毁**，只被摘下 / 放回（示例按钮的监听还在它上面）。
- **失败行在「这段编号刚生成」时不出现**（照旧摆横幅）：一段新编号没有内容可失败，报「没加载出来」是纯噪音。这是「事实表」里 `app.py:331-333` 那行推出来的 —— 票面的四态表没分这一叉。
- **`cancelRename(input, title)` 改成显示原来的标题**。旧版放的是输入框里那个半成品：按 `Escape` 之后列表上显示你刚敲的名字，而库里一个字没改。票面只点名了失败行为，但验收那条「名字还原」要求它。
- `renderList` 的空列表文案靠 `searchTerm`，它现在的语义是**已提交的**那个词。

### 二、与票面不一致的三处（核代码 / 真机之后改的）

1. **任务 2 说「两道原有守卫必须留着」，`!input.isConnected` 我没留。** 票面（连同我写它时的推理）假定「失焦时输入框已经摘掉了」；真机量到的是**相反**：DOM 的移除步骤**先**跑焦点修正、**后**真摘节点 —— 在 blur 回调里 `input.isConnected` 还是 `true`（而 `document.activeElement` 已经回到 `BODY`）。所以留着那条守卫**拦不住 `Escape`**：按 Escape 会紧跟一次提交（真机抓到：标题被写成了输入框里那个值）。改成推一个**微任务**再问 `isConnected`。`busy` 那条照留。
2. **任务 4 说「不新增状态」，实际新增了一个模块级布尔。** 那句原意是「不新增 *UI* 状态」（画面还是四种），但「这段编号是不是刚生成的」总得有个地方存 —— 它落在 `loadConversationId()` 已有的两个分支上。代码审查指出它**写四处、只读一处**（两处是死的），已收成**一写一读**并改名 `mayHaveHistoryAtBoot`，把范围说准（只管首屏那一拍）。
3. **验收那条「刷新页面 → 横幅不先蹦出来」的口径改小了。** 消掉的是 `clearChat()` 主动把横幅放回去那一跳 —— 就是用户抱怨的那一跳。但那份横幅是**服务端渲染**的，要等 module（先 import 那个 vendored parser）跑起来才会被摘，这一小段窗口我**没能证到零**：量到的是 `DOMContentLoaded` 时横幅已经不在、转圈在场，但「解析期间有没有画出那一帧」抓不到。真机上我没看见闪，但**不能说它为零**。

### 三、多做的两件

### 十、收尾之后追加的一条（2026-09-23 晚，用户提的）

> 「会话列搜索时，列表要有圆圈加载中的提示」

**改了任务 4 那半句**（「转圈只放聊天区，左栏不动」）—— 见任务 4 里那条就地补的注。落法：

- `loadConversations(options)` 多收一个 `searching`：只有**搜索那一行**发起的请求（按下搜索 / 清空输入框）才 `showListLoading()`；首屏、每轮答完、三个管理动作之后的刷新都**不摆** —— 那些是列表在**原地**重拉，摆一下就是闪。

- **失败要有终点**（转圈不能永远转）：收掉转圈，出一行「列表没加载出来, 再按一次搜索」。**不说「没搜到相关的对话」** —— 那是另一件事（后端确实筛过了、只是没命中）。重试的路没堵：搜索框还在，再按一次就是重试（而且不再因「词没变」被挡掉）。
