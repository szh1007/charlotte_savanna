# PRD — 万能视频下载站 (video-downloader)

> Status: `ready-for-agent`
> 来源：`/grill-with-docs` 方案商讨（2026-08-19 人工确认）
> 领域术语表：`project/video_downloader/CONTEXT.md`；架构决策：`project/video_downloader/docs/adr/`（ADR-0001 ~ 0003）

## Problem Statement

许多用户有把在线视频保存到本地的需求，但各平台普遍存在下载障碍：

- **平台不支持下载**：视频页不提供下载入口，或只有低清晰度试看档
- **下载不便**：不支持批量下载、单次只能下载一个、需要逐集手动操作
- **清晰度受限**：平台限流或付费墙限制，最高只能拿到 720p 甚至更低
- **多平台碎片化**：不同平台需要不同的工具或在线解析站，学习成本高
- **移动端支持差**：PC 端工具无法在手机上随时随地使用
- **在线解析站体验差**：广告泛滥、解析链接频繁失效、存在安全风险（恶意脚本/隐私泄露）

目标用户为学习/收藏场景（下载课程视频、素材、备份自己的内容）的学生群体，对工具的**实用价值**（能下载、快、支持平台多、手机可用）有强需求；同时也存在愿意为「更高清晰度、更大队列、更高并发」付费解锁的意愿，这是项目可持续性的关键假设。

## Solution

一个**万能视频下载网站**：用户在输入框粘贴视频页面链接 → 一键解析出视频元信息与可用清晰度档位 → 选择档位发起下载 → 任务在队列中执行 → 完成后生成**临时直链**，在手机/电脑上随时保存文件。

产品形态与技术路线：

| 维度 | 方案 |
|------|------|
| 核心流程 | 粘贴链接 → 解析 → 选档 → 下载 → 直链交付 |
| 下载引擎 | 开源项目 yt-dlp（Unlicense，支持约 2000 个平台），Python API 嵌入，零代码改动继承引擎能力（ADR-0001） |
| 后端 | FastAPI + uvicorn，**无数据库**，任务/队列/交付链接全部内存态 + TTL 过期清理（ADR-0003） |
| 前端 | Vue 3 + Vite 独立工程，手写样式零 UI 库，深色 Hero + 粉紫渐变（参考 ai.codefather.cn/painting），**营销导向**突出付费价值 |
| 付费能力 | 会员密钥验证（MEMBER_KEY）+ 后端强制真实功能差异：免费限 720p/1 并发/队列 5/直链 24h；会员解锁全部清晰度/3 并发/队列 50/直链 72h（ADR-0002） |
| 批量下载 | 队列机制支持一次提交多个任务顺序执行，配合并发槽分配调度 |
| 免责与安全 | 版权免责声明（仅个人学习使用）、不破解 DRM、不绕过付费墙，封号风险用户自担 |

## User Stories

### 解析与发现

1. 作为一个普通用户，我想在首页看到一个醒目的链接输入框，以便我能立刻开始使用，无需注册登录
2. 作为一个普通用户，我想粘贴任意平台的视频页面链接（B 站/抖音/YouTube/小红书等），以便解析其下载信息
3. 作为一个普通用户，我想点击「解析」后看到视频的封面、标题、平台来源与时长，以便确认视频内容无误
4. 作为一个普通用户，我想看到解析出的全部可用清晰度档位（如 360p/720p/1080p/4K/最佳画质），以便选择符合我需求的档位
5. 作为一个普通用户，我想在解析前就知道哪些清晰度档位需要会员才能解锁，以便决定是否开通会员
6. 作为一个普通用户，我想在输入非法链接或不受支持的平台链接时看到明确的错误提示，以便我知道如何修正
7. 作为一个普通用户，我想看到网站支持哪些平台（平台卡片墙），以便判断我的视频来源是否可用
8. 作为一个用户，我想看到平台卡片展示支持的格式类型（如 MP4/FLV/4K），以便在下载前了解质量上限
9. 作为一个普通用户，我想在解析过程中看到「解析中…」的加载状态，以便我知道系统正在工作而不是卡死

### 下载与队列

15. 作为一个普通用户，我想对失败的任务重新发起下载，以便无需重新粘贴链接

## Implementation Decisions

### 1. 架构总览

- **三组件**：Vue 3 + Vite 前端（独立工程）↔ FastAPI 后端 ↔ yt-dlp 引擎（+ ffmpeg 音视频合并）
- **后端无数据库**：任务/队列/会话全部内存态（ADR-0003），依赖最少
- **单进程部署**：uvicorn 单进程；后台调度线程 + 清理线程
- **前端独立开发约束**：不参考本仓库其他 demo/子项目，视为独立无参考的新工程，仅依赖本 PRD 与提示信息

### 2. 下载引擎（ADR-0001）

- 直接使用 yt-dlp（Unlicense），通过 `yt_dlp.YoutubeDL` Python API 嵌入后端，不 fork、不修改源码
- **解析**：`extract_info(url, download=False)` 提取标题/封面/时长/站点/格式列表
- **下载**：按选定 `format_id` 下载，`merge_output_format=mp4` 保证输出单一 MP4 文件；音视频分离流由 ffmpeg 合并
- **进度上报**：`progress_hooks` 回调转发到任务状态（百分比上限 99.0，100 仅在完成后标记）
- **错误透传**：失败原因以 yt-dlp 异常信息为准，不自行猜测翻译
- **能力边界**：引擎不破解 DRM，本项目同样不提供任何绕过能力；引擎升级 = pip 升级，零代码改动
- 环境依赖：ffmpeg 需预装（winget 全局安装）

### 3. 任务模型与状态机（领域核心）

- **下载任务 (DownloadTask)**：一个来源链接 + 一个选定格式档位 + 一份状态；resolve 与 download 两种任务类型共享同一状态机与并发槽
- 状态机（来自方案确认，决策级内容保留）：

```
pending → resolving → resolved → queued → downloading → completed
                              ↘                ↘
                               failed            failed
completed/expired → expired（交付链接过期，文件被清理）
```

- `pending` 新建待解析；`resolving` 解析执行中；`resolved` 已解析等待入队；`queued` 排队中；`downloading` 执行中；`completed` 文件就绪并生成交付直链；`failed` 出错（含超时、引擎拒绝）；`expired` 交付链接过期
- 任务存储：线程安全内存 dict（RLock 保护），按创建时间降序返回

### 4. 并发调度与批量队列

- **并发槽**：resolve 任务与 download 任务共享并发槽位；免费档 1 个、会员档 3 个
- **调度模型**：后台调度线程周期性（约 0.5s）扫描队列，把排队任务分配到空闲槽位；会员任务优先
- **队列上限**：免费 5、会员 50；超限拒绝创建并返回明确错误
- **频率限制**：免费档宽松限速（解析/下载频率），会员不限

### 5. 付费差异（后端强制，非 UI 摆设）

| 能力 | 免费档 | 会员档（密钥） |
|------|--------|----------------|
| 清晰度 | 仅 ≤720p（更高档位标记锁定） | 全部（1080p/4K/最佳画质） |
| 并发下载数 | 1 | 3 |
| 批量队列上限 | 5 | 50 |
| 交付直链有效期 | 24h | 72h |
| 解析/下载频率 | 宽松限速 | 不限 |

**强制校验点**：
1. 解析结果中 >720p 档位对免费用户标记 `locked`
2. 免费用户选择被锁档位时后端拒绝
3. 下载执行前对非会员任务重新校验所选档位清晰度（防止绕过），违规拒绝
4. 并发槽、队列上限、直链 TTL 均按会员身份后端计算

### 6. 会员鉴权（ADR-0002）

- `.env` 配置单一会员密钥 `MEMBER_KEY`；前端输入密钥 → 后端校验 → 通过则生成**内存态会话 token**（24h TTL）→ 后续请求通过 `X-Member-Token` header 携带
- 密钥是共享的（所有会员同一密钥），不模拟账号体系；未来接真实支付时仅替换「密钥校验」为「订单回调」，付费差异逻辑全部保留
- 环境变量通过 `.env.example` 提供模板（占位符），真实密钥不入库

### 7. 交付文件与 TTL 清理（ADR-0003）

- 交付文件落 `downloads/` 目录（.gitignore）
- 后台清理线程周期扫描（约 60s）：`completed` 超 TTL 的任务 → 删除文件 + 标记 `expired`
- 服务重启后所有任务作废，内存态不持久化
- 未来需持久化时替换存储层即可，状态机不变

### 8. API 契约

| 方法 | 路径 | 说明 | 请求 → 响应 |
|------|------|------|-------------|
| POST | `/api/resolve` | 解析链接元信息 | `{url}` → `{task_id, title, cover, duration, site, formats[], member_limited}` |
| POST | `/api/downloads` | 创建下载任务 | `{url, format_id}` → `{task_id}`；队列超限返回 429 |
| GET | `/api/tasks` | 任务列表（降序） | → `{tasks: Task[]}` |
| GET | `/api/tasks/{id}` | 单任务详情 | → `Task` |
| GET | `/api/events` | SSE 进度流 | `?task_ids=1,2` → 事件流 |
| GET | `/api/files/{id}` | 交付直链下载 | → 文件流；已过期返回 404/410 |
| POST | `/api/member` | 提交会员密钥 | `{key}` → `{is_member, expires_at}` |
| GET | `/api/member/status` | 会话会员状态 | → `{is_member}` |
| GET | `/api/sites` | 支持平台列表 | → `{sites: [{name, icon}]}` |

**SSE 事件协议**（`event: task-update`）：`{task_id, status, progress, message, url?, error?}`；心跳约 15s；客户端断开需检测并清理

### 9. 支持平台展示

- 页面展示平台卡片墙（约 12 个精选平台：哔哩哔哩/抖音/YouTube/小红书/微博/快手/西瓜视频/腾讯视频/优酷/爱奇艺/Twitch/Vimeo），数据来源于引擎能力清单；引擎实际支持约 2000 个站点

## Testing Decisions

**测试 seam 已确认（2026-08-19）**：以 **HTTP API 层为主 seam** —— 所有自动化测试通过 FastAPI TestClient 打 HTTP 接口断言行为；内部状态机、并发调度、付费差异均通过 HTTP 行为验证，不直接测试内部函数实现细节。

- **测试原则**：只测外部行为（HTTP 请求 → 响应/SSE 事件），不测实现细节；一个测试验证一个行为
- **引擎隔离**：yt-dlp 调用集中在引擎封装模块，测试中 mock 该模块（fake 解析结果/下载过程/异常），保证测试套件无真实网络依赖、快速稳定
- **覆盖范围**：
  - 解析接口：合法链接 → 返回元信息与档位列表；非法链接 → 明确错误
  - 付费差异：免费用户解析结果中 >720p 档位标记锁定；免费选择锁定档被拒；下载前档位重校验；会员 token 有效/无效/过期场景
  - 队列与并发：免费 1 并发/会员 3 并发行为验证；队列上限 5/50，超限返回 429；会员任务优先调度
  - 状态机流转：通过 SSE 事件流断言 pending→resolving→…→completed/failed 全链路；失败状态携带错误信息
  - 交付与 TTL：完成后直链可下载；TTL 到期后文件清理、任务标记 expired、直链返回 404/410（时间用可注入时钟 mock）
  - 会员接口：正确密钥 → is_member=true；错误密钥 → 明确拒绝；状态查询
  - 平台接口：返回非空平台列表
  - SSE 心跳与断开清理
- **E2E（单独验证，不进自动化套件）**：真实链接走完 解析→下载→SSE→直链 全链路；会员解锁 1080p 真实下载；前端浏览器验收 + 端到端演示
- **验收标准**：自动化测试全绿；真实链接 E2E 通过；前端完成浏览器逐块验收
