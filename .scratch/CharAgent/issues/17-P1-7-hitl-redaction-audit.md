# 17-P1-7 — HITL 审批 + 敏感信息脱敏 + 审计轨迹

> **2026-09-18 修订（两轮）**：
> 1. （ADR-0009）新增**第二条挂起路径「用户确认」**，与内部审批**代码不得耦合**
> 2. （ADR-0010 + 边界复核）**策略归位** —— 本 issue 只做**机制**。原先写在这里的「金额分层（≤ 阈值自动通过）」「主管/风控审批」「`confirm_token` 校验」都是**业务策略**，已移出：阈值与规则在工具实现里（`CharService/issues/07`）、角色名单在审批端点（同 07）、凭据签发与校验在网关（`CharService/issues/08`）。分工以 ADR-0009 的「实现归属」表为准

**What to build:** HITL 审批的**机制层**：

- **挂起 → 落盘 → 恢复**：工具返回 `Suspension`（通道见 P1-15）→ loop 落帧 → 发 `approval_required` / `confirmation_required` 事件 →（经 P1-1 的两个控制面端点）从挂起 checkpoint 恢复执行（**不重跑**）/ 拒绝后失败原因回填模型继续推理 / 超时（默认值可配）自动拒绝走降级
- **两条路径不耦合**：两种 `SuspensionKind` 各自独立可测
- **挂起记录携带 initiator**：供应用判定「发起方不得审批自己发起的挂起项」
- **审批鉴权可注入**：框架提供钩子、默认放行——角色名单与 SoD 规则归应用
- **PII 结构化脱敏**（日志/审计前置）+ **审计落库接口**（工具调用粒度；数据访问粒度由网关侧产生，见 `CharService/issues/04`）

**Blocked by:** 11, 12, 35

**Status:** ready-for-agent

- [ ] 挂起 → 落盘 → 恢复（不重跑，验证已执行步骤不重复）（#25）
- [ ] 拒绝 → 失败原因回填模型继续推理（#25）
- [ ] 超时降级：默认值可配 + 自动拒绝走降级路径（#25）
- [ ] **两条路径不耦合**：`approval_required` 与 `confirmation_required` 各自独立可测，无共享分支
- [ ] **挂起记录带 initiator** —— 用例：同一条挂起，不同 initiator 可被判出不同结果
- [ ] **审批鉴权钩子可注入**（默认放行）—— 用例：注入一个「发起方不得自批」的钩子后，自批被拒且原因是可操作错误
- [ ] PII 结构化脱敏：日志/审计中 PII 与 API Key 脱敏（#26）
- [ ] audit_logs **工具调用粒度**（谁 / 代表谁 / 工具名 / 参数摘要 / 耗时 / 结果），脱敏后写入（#27）
- [ ] E2E 测试：恢复 + 拒绝 + 超时 + 用户确认**四条路径**（「自动通过」不在此列——由应用侧判定，框架无活可干）
- [ ] **挂起帧落点端到端验证**（P0 预埋路径，零真实产生者）：`state.suspension` 在生产代码里目前**零赋值点**，测试里的挂起帧是手拼的。接线时要定清三件事——审批前**在哪一行落帧**、谁写 `state.suspension`、写什么。落帧点决定补做范围：落早了会把已执行的工具当欠账重跑，落晚了则该轮的 `tool_call` 与结果都没进过快照（与 `06-boundaries.md` §6.8 是同一个窗口）。用例：真造一次挂起（审批前落帧 + 真走 `resume`）→ 断言工具**只执行一次**、`turn_count` 接续、新帧 `parent_id` 指向挂起帧。**补做挂起调用前必须先查幂等表**，否则审批通过后的补做会把副作用工具跑第二遍
