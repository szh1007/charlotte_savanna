# ADR-0008: 业务系统对接形态——业务 internal API + 内部网关 + 身份服务三层

- 状态: accepted
- 日期: 2026-09-18
- 修订: ADR-0004（其「订单表通过独立只读查询层直连 MySQL」的条款被本 ADR 取代；「通用框架 + 电商售后客服 demo 双形态」的核心决策不变）
- 考虑过的方案:
  - **工具直连业务库**（ADR-0004 原方案）—— 推翻：绕过业务规则（能否退款取决于状态机 + 风控，不在表里）、写操作绕过事务与领域事件、表结构是内部实现而非契约、权限与审计断链，且分库分表下物理连不上
  - **1:1 封装现有买家端点 + 加 Token 认证** —— 拒绝：端点都是买家自用视角（`user=request.user`），工具签名的形状由页面而非任务决定，一个客服问题要模型串 3-4 次调用；且推荐/退款/发货端点根本不存在
  - **独立 BFF 服务聚合** —— 拒绝：多一个服务要启停/测试/部署，退款数据落在 BFF 侧与订单数据分离使跨系统一致性（Saga）变成真问题，而「现有端点无 Token 认证」这个摩擦点依旧存在
  - **现成网关（Kong / APISIX）** —— 拒绝：学习重心从「实现」变成「配置」，且委托 token 的双主体语义要自己写插件，协议适配层不在手里
- 后果: 组件数 +2（内部网关、身份服务）；minimall 新增 internal/support 命名空间与退款能力；业务代码独立成 `CharService/`；agent 侧不再持有任何业务凭证。**框架层不因业务对接形态而改动**——但另有两条**通用能力**的缺口由此暴露，见 [ADR-0010](0010-runtime-context-and-suspension-channels.md)（运行时上下文注入 + 挂起信号通道），那是框架自身的演进，与业务无关

## 上下文

P0 交付后项目进入 P1，原计划由「客服 demo」一个任务承载业务落地：工具只读直连 minimall 的 MySQL（ADR-0004），目的是演示难点 #24（工具沙箱 / 最小权限）。该形态在纯学习维度成立，但作为「企业级电商智能客服」的对照物不成立——企业里 agent 从不直连业务库。

同时盘点发现 minimall 的现状无法支撑原计划：24 条路由全部是买家自用视角且**仅 Session Cookie 认证**（无 Token/JWT），**无推荐端点**（`is_featured` 字段未暴露为 filter）、**无退款端点**（`Order.Status.REFUNDED` 枚举值存在但全仓库无代码路径能置为该状态）、**无发货 REST 出口**（仅 Django admin 的 `queryset.update()` 批量动作）；余额侧无账本、无幂等、`pay_order` 无 `select_for_update` 保护。

## 决策

**三层结构，agent 只碰最上一层。**

1. **业务系统**（`app/minimall/`）——新增 `/api/minimall/internal/support/*` 命名空间，独立于买家端点；端点**按任务粒度**设计而非 1:1 映射资源（例如 `GET orders/{order_no}/support-view` 一次返回订单 + 物流 + 售后资格）；缺失能力在业务系统内补齐——退款单（含状态机）、余额流水、推荐查询、发货端点
2. **内部网关**（`CharService/gateway/`）——agent 调业务系统的**唯一入口**，承担认证（验委托 token）+ 限流 + 审计 + 转发；因为它是唯一入口，**限流与审计不可绕过**（工具层代码里根本没有业务系统的地址与凭证）
3. **身份服务**（`CharService/identity/`）——把会话绑定的 `user_id` 换成一个带 `act`（代理方）语义的委托 token；详见 ADR-0009

**工具是薄封装**：只做参数校验 + 调网关 + 结果格式化，业务逻辑一律不下沉到工具里。这条约束使得 P2 阶段把同一批工具包成 MCP server 时**零改动**。

**分期原则不破**：P1 用进程内 `@tool` 直调网关，不引入 MCP——MCP client/server 是 P2 的交付物，若 P1 依赖它则「P1 验收不受 P2 进度影响」（ADR-0007）失效。耦合方向是单向的：P2 消费 P1 的产物。

## 决策记录

- 业务对接形态定为三层，工具改走网关而非直连库（2026-09-18 访谈 Q2/Q4/Q5）
- 业务代码独立为 `CharService/`（与 `CharAgent` 统一前缀），框架保持业务无关（2026-09-18 访谈 Q9）
